## 四、推荐路线：分阶段，不要一次上全套

### 阶段一（1–2 周）：路径 A 打底

- **做什么**：三份 Markdown 文件 + `§` 分隔 + 字符预算；DSH 插件做 `systemPrompt.assemble` 注入 + `appendPluginRecord` 快照；`memory` 工具做「读前校验 + 服务端版本 CAS」；租约锁 + 原子写 + 本地 Git。
- **为什么先做它**：零外部依赖、人可读、可审计、**随时能迁出**。Amadeus 已证明这套在 DSH 上跑得通，`dsh-memoir` 已明确支持你的 `0.2.0-rc.2`。
- **验收**：新会话能看到注入段；并发写第二个写者被拒且不改盘；杀进程后文件不损坏。

### 阶段二（1–2 周）：按需补路径 B 的检索

- **只在阶段一真的痛了才做**（痛点是"存了但搜不到"）。
- **最小改动**：保持 Markdown 为权威副本，加一层 SQLite 索引（中文分词 + BM25 混合重排）。索引坏了可从文件重建。
- **验收**：**先做对照实验**——同一批中文记忆，默认分词 vs bigram，20 个真实查询的命中率差多少。没数据就别继续。

### 阶段三（可选）：路径 C 做解耦出口

- 当你担心"DSH 破坏式更新"或想跨 agent 共享时再做。
- 优先做**只读** MCP 出口（把记忆暴露给外部客户端查），写入仍留在 DSH 插件里——风险最小。

### 阶段四（谨慎）：路径 D 只在大记忆量时引入

- 优先选**有官方 DSH 插件 + Apache-2.0 + 能导出**的：MemOS / ReMe / EverOS。
- **必须关掉自动整合**（原因见第六节）。

Amadeus 的价值不在代码（无许可证，不能搬），在**流程**。它的 `docs/research/` 里躺着一条完整的研发时间线：

```
2026-10-08  personal-agent-memory-survey.md          ← 先做 98KB 的 prior-art 调研
2026-10-09  amadeus-personalization-plan-draft.md    ← 计划草稿，明确标注"待设计项≠接口"
2026-10-09  personalization-tools-files-design.md    ← 工具与文件设计
2026-10-10  personalization-implementation.md        ← 实现记录
2026-10-11  dsbot-memory-comparison.md               ← 横向对比
2026-10-11  memory-provenance-and-browser-capacity.md ← 较新的规则，冲突时以它为准
```

配套的 `AGENTS.md` 约定（原文口径，值得抄到你的项目——**但要先看清它的性质**）：

> ⚠️ **`AGENTS.md` 是文档，不是门禁。** 它只影响"模型愿不愿意遵守"，无法决定"系统允不允许发生"；换模型、上下文被压缩、被注入文本覆盖都会让它失效。**下面是可抄的条款，但每一条都要配一个测试或守卫**，否则只能算软约束。硬化方案见 [06-约束硬化设计.md](06-约束硬化设计.md)。

1. **需求依据指向单一权威文档**；旧文档与新文档冲突，以新版为准；`docs/research` 的历史记录**不随版本批量改写**。
2. **不改写 `node_modules` 里的 DSH 代码**；定制一律走公开扩展点；确实没有扩展点时，先说明取舍再决定，不擅自复制原生插件。
3. **每个行为改动都要有单元测试**（`node --test tests/*.test.mjs`）；涉及界面的跑真实浏览器脚本；**无法自动化的如实标注"需人工验收"，不宣称已验证**。
4. **发布用 `npm run pack:plugins`** 输出归档 + `SHA256SUMS`；升级时保留上一镜像标签用于回滚。
5. **文件缺失或编码异常时降级加载，不能让对话整体失败**；但**初始化失败要响亮报错**。

**第 5 条的反面教材值得单独记住**：Hermes 有过一个真实事故——`int(mem_config.get("nudge_interval", 10))` 抛错被外层 `except Exception: pass` 吞掉，**整个记忆子系统静默失效且不报任何错**。

> **更新（2026-10-17）**：后来找到了比 Amadeus 更合适的参照实现——[`tigerless-labs/agent-memory`](https://github.com/tigerless-labs/agent-memory)（**4,004★ / MIT / 活跃**）。它与路径 A 同哲学（Markdown 为真相、本地检索、无 API key），但**成熟度和设计细节都强于 Amadeus**（后者 3★、无许可证，法律上不可复制代码）。**读代码请读它，Amadeus 只作流程范本。** 精读见 [09](09-agent-memory项目精读与采用建议.md)。

## 六、中文社区的共识与一条硬警告

我在知乎找到三篇直接相关的内容（CSDN 有反爬，正文未能取得，仅保留线索）。

### 共识一：记忆要分层，别混成一个桶

高赞答案给出的 **L0–L4 权威分层**（原文口径）：

| 层 | 内容 | 权威性 |
|---|---|---|
| L0 | 工作记忆（当前任务） | 最高，随任务消失 |
| L1 | 显式长期记忆（用户明确说的偏好/事实） | 高，用户可编辑 |
| L2 | 从历史抽取的事实 | 中，需可回溯 |
| L3 | 自动积累的经验 | **低，可衰减** |
| L4 | 正式能力（Skill） | 经审批发布 |

**建设顺序也给了**：先做 L1 显式记忆 → 再统一 `MemoryContext`（身份/权限/作用域/冲突/token 预算）→ L2 试点 → L3 离线学习并用影子评测证明有效 → L4 发布。

**这条对你最有用**：不要一上来就做 L3（自动经验）。先把 L1 做扎实。

### 共识二：写入和检索都有明确的"门槛"，不是有就存、有就取

另一篇设计长文给了可直接抄的规则：

**写入前五问**：未来会复用吗？足够稳定吗？与用户/项目/任务有关吗？已经存在同类吗？涉及隐私吗？
**禁止写入**：敏感凭据、单次闲聊情绪、未确认的猜测、无关的对话全文。
**检索四触发**：用户提到"上次/之前/继续/按我的习惯"；任务属于长任务（写报告/写代码/调试/研究/规划）；上下文水位超 80%；相似度超阈值。
**注入上限**：最多 3–5 条记忆卡片（原文原话："每轮都注入 20 条记忆就是危险信号"）。

### 共识三（**最重要**）：别急着自动总结

知乎那篇解读论文的文章给的数字很刺眼：

> **GPT-5.4 不用记忆时 100% 做对 19 道题，记忆整合 10 轮后准确率掉到 52.6%。**

论文（[arXiv 2605.12978](https://arxiv.org/abs/2605.12978)）的五条工程结论：

1. 原始经历与提炼经验**分开管理**，不能揉进一个反复被改写的文件；
2. 记忆整合**要过门槛**，不要任务一结束就自动总结；
3. 提炼**要慢**，先积累证据再提炼；
4. 写进去的经验**要能验证**；
5. 出错**能撤回**、不可靠**能标记**。

**这条直接决定了四份文档里反复出现的三个设计约束**：
- 自动**捕获**可以有，自动**整合/改写**应默认关闭；
- 每条记忆留 `source`（哪次会话、哪条消息）；
- 事实失效用**标记**（`invalid_at`）而不是物理删除。

4. **你愿意写 TypeScript 插件吗？** 还是希望"装个包就能用"？（→ 决定 A/B 自研 vs D 采用）
