## 0. 本版改了什么（v1.1 → v1.2）

| # | 改动 | 为什么现在改 |
|---|---|---|
| 1 | **Windows 持久化策略写死**：fsync 临时文件 → rename；**不承诺目录项持久**（Windows 不能对目录 FlushFileBuffers），用 txn + ledger 做崩溃可检测 | v1.1 只说"接受取舍"，没给步骤与验收 |
| 2 | **类型冻结**：附录 F 直接给出 `MemoryDoc`、`RecordInput`、`ProposalInput`（5 变体）、`WriteResult`、`RecallResult` | v1.1 说"S2a 前冻结"，但没内容；实现时最耗时的就是这项 |
| 3 | **S2a 加一条薄纵切**：`mem read` + `mem recall`（子串）——S2 结束就有"写入→读出→重建后仍读出"的闭环，不必等 S3 | v1.1 的 S2a 只有 add/rebuild，没有用户可见的"读" |
| 4 | **decisions 不变量与重放顺序**：删除决定必须指向存在且活动的 id；按 op_id 幂等；rebuild 先文件后 decisions | v1.1 说 decisions 是第二真相源，但没定冲突规则 |
| 5 | **ledger tripwire**：manifest 记 `ledger_head {seq, hash}`，doctor 校验未缩短、链未断 | 防止"台账被截断但文件还在"的静默失效 |
| 6 | **closeout 生命周期**：注册 `closeout_submit` → `followup` → `await whenIdle()` → dispose；工具表快照测两态 | 不 dispose 会永久扩大模型工具面 |
| 7 | **token 预算双轨**：`estimateMessage(合成 system 消息)`；不可用则 `chars ÷ 2.5` 粗估并标"估算"；两值都记录 | 字符预算与 token 预算不能只留一个 |
| 8 | **构建产物契约测试**：对 `dist/plugin.mjs` 断言"无 import 语句、导出 apply/inject" | v1.1 只有源码测试，打到 bundle 的回归测不到 |
| 9 | **召回评估拆 dev / held-out**：30 + 10 条查询；per-kind Recall@5、无答案误返回、p95、冷启动、常驻内存 | 单集合调参会过拟合；v1.1 只提"先冻结" |
| 10 | **CLI 与工具一致性**：同一查询两侧结果一致；同一写入两侧校验一致 | v1.1 把它列在测试类别，没进验收 |
| 11 | **ENOSPC 与长路径**：磁盘满失败干净；>240 字符 home、中文/空格路径 | Windows 上最容易漏的两类 |
| 12 | **术语表**：目录/索引/台账/账本/提案/决定/隔离 统一口径 | 文档里这几个词已出现混用 |
| 13 | **外部检索说明**：web 正文抓取被环境挡住，只用到了搜索索引的标题；外部结论一律标"未核验"，不据此改决定 | 避免把没读过的页面当依据 |

## 2. 保证分级与范围

### 2.1 三级表述

| 级别 | 含义 | 例子 |
|---|---|---|
| **机器保证** | 有代码检查 + 会失败的负向测试 | 工具表无 `decide`；零宽字符被拒；压缩不 shadow node 0（M2 后标注） |
| **尽力而为** | 有检查但不能证明完备 | 密钥正则扫描；注入模式检测 |
| **不承诺** | 依赖模型/外部系统 | 模型遵守 `[模型指引]`；缓存命中；DSH 升级后行为不变 |

### 2.2 做什么 / 不做什么

同 v1.1 §2.2–2.3：Core 六件事（存储、有效期、检索、索引、审计、策略）；DSH 适配（5 工具、注入、来源绑定、`/closeout`）；CLI 全命令；安全（扫描、隔离、封存、篡改检测）。不做向量/FTS5/自动整合/Web/MCP/付费/多租户/原始会话副本。

**本版新增一条边界**：Windows 上不承诺"rename 返回即代表断电后仍在"；只承诺"崩溃后状态可检测、可恢复、不静默丢数据"。这写进 README。

### 3.3 技术选择

| 领域 | 选择 | 约束 |
|---|---|---|
| 运行时 | Node 24.21.0（`.node-version`） | `npm run compat` 校验；开发机 25.2.1 只作日常 |
| 语言/构建 | TypeScript strict + `erasableSyntaxOnly`；esbuild | 禁 enum/namespace/参数属性 |
| 测试 | `node:test`，默认单进程 | 沙箱不能 spawn 管道 |
| 权威存储 | 一记忆一文件，创建后不可变 | 索引/缓存永不当真相 |
| 元数据 | 每行 `key: <JSON>` + `JSON.parse` | 拒绝重复/未知/多行 |
| 检索 | 字段加权 BM25（内存）；S2a 先用子串 | 不做 Retriever 抽象 |
| 索引 | `.index/manifest.json` + 启动时内存倒排 | 删掉可重建 |
| 审计 | `audit.jsonl` 可轮转；`.state/ledger.jsonl` 不轮转 | 台账是隔离判据 |
| 并发 | 独占锁 + 租约（15s 心跳 / 5min 且 PID 不存活判陈旧 / 60s 超时） | 仅本地 NTFS |
| 持久化 | 临时文件写后 `fs.fsync(fd)`，再 rename | **目录项不 fsync**（Windows 不支持），README 声明 |
| token | `ctx.tokenMeter.estimateMessage`；兜底 `chars ÷ 2.5` 并标"估算" | 两值都记录 |
| 依赖 | 运行时零依赖；DSH 包是 peer（S3 起加精确版本 devDeps 供类型） | `dsh.bundle.patch` 形态 |

## 4. 数据模型

### 4.1 磁盘布局

```text
<home>/
├── config.toml  policy.json
├── SOUL.md  USER.md  RULES.md
├── MEMORY.md                               派生视图
├── memories/{fact,pitfall,exp}/<id>.md     权威、不可变
├── proposals/pending/<proposal-id>.json
├── proposals/decisions.jsonl               决定账本（哈希链）
├── audit.jsonl                             可轮转
├── .index/manifest.json
└── .state/{lock,txn/,ledger.jsonl,snapshots/,policy.seal.json}
```

### 4.2 单条记忆

frontmatter 每行 `key: <JSON>`；字段与 v1.1 §4.2 相同（`id`、`mem_schema`、`kind`、`scope`、`abstract`、`created_at`、`valid_from`、`valid_until`、`supersedes`、`author`、`evidence_level`、`error_signatures`、`provenance`、正文）。本版补两条：

- `created_at` 与 `valid_from` **分开**：`created_at` 是写入时刻（ISO 带时区），`valid_from` 是生效日期（事件日期或当天）。
- `error_signatures` 仍是字面子串、≤3 个、每个 ≤80 字符；不做正则。

### 4.3 RULES.md

同 v1.1：`[机器门禁]` 必须有 `check:` + `test:` + `[neg]` 用例；`[模型指引]` 不得冒充保证；agent 无写入口；三文件规范化哈希并入封存（S5）。

### 4.4 MEMORY.md 目录

- 每行 `- [kind] abstract — id`；只列活动项；确定性优先级 `evidence_level → valid_from → id`。
- 分档只决定目录详细程度，正文永不常驻；>200 条时只列高优先条目 + 计数 + 提示。
- 裁剪不删记忆；被裁条目仍可召回。

### 4.5 有效期与替代

- 文件不可变；修订 = 新条目 `supersedes: [旧]`。
- 有效终点 = `min(valid_until, 所有后继的 valid_from)`；活动 = `[valid_from, 终点)`。
- 禁止成环、自引用、重复；后继 `valid_from` 不得早于被替代者。
- `recall` 默认今日活动；`as_of` 指定日期；历史链可 `read` 追溯。

### 4.6 删除、合并、拆分

| 操作 | 表达 | 不变量 |
|---|---|---|
| 删除 | `decisions.jsonl` 的 `{op:"delete", target, at, base_hash, actor, reason}` | target 必须存在且当前活动；按 `op_id` 幂等；源文件保留 |
| 合并 | 1 新 `supersedes:[旧1,旧2,…]` | 新旧来源都要能核验 |
| 拆分 | N 新各自 `supersedes:[旧]` | 允许一个旧条目有多个后继 |
| 物理删除 | `mem purge <id> --accept`（S7） | 文件 + manifest + 目录项；decisions 留墓碑 |

**重建顺序**：先读文件（权威），再按 `decisions.jsonl` 顺序应用删除/决定，冲突（文件缺失但无 delete、或 delete 指向不存在）→ 隔离并入 `doctor` 报告。decisions 自带 `prev` 哈希链；被删改可检测。

## 5. 服务、工具与权限

### 5.1 MemoryService

```ts
interface MemoryService {
  recall(q: RecallQuery): Promise<RecallResult>;   // { hits, warnings }
  read(id: MemoryId): Promise<MemoryDoc>;
  asOf(q: RecallQuery, date: string): Promise<RecallResult>;
  rules(): Promise<Rule[]>;
  stats(): Promise<Stats>;
  record(input: RecordInput, actor: TrustedActorContext): Promise<WriteResult>;
  propose(input: ProposalInput, actor: TrustedActorContext): Promise<Proposal>;
  decide(id: ProposalId, d: 'accept' | 'reject', human: HumanApprovalContext): Promise<void>;
  add(input: RecordInput, human: HumanApprovalContext): Promise<WriteResult>;
  adopt(id: MemoryId, human: HumanApprovalContext): Promise<WriteResult>;
  rebuild(): Promise<RebuildReport>;
}
```

类型形状见附录 F（S2a 第一步落地为 `model/types.ts` 并由单测锁定）。`decide`/`add`/`adopt`/`rebuild` 只有 CLI 构造的 `HumanApprovalContext` 能调；`decide` 不注册为工具。

### 5.2 模型工具（5 个）

`memory_recall`（默认 `recall.limit` 条）、`memory_read`（带来源头、按 §6.1 转义）、`memory_record`（T0，模型只给内容与 `evidence[{event_seq, quote}]`）、`memory_propose`（T1，必须带 `base_hash`）、`rules_list`。

工具表快照测试：集合等于上表；`additionalProperties:false`；字段名不含 `path`/`target`/`session`/`approve`。

### 5.3 可信来源

模型给 `{event_seq, quote}` → 适配器经 `ctx.sessionPersistence`（或 live session）读事件 → 校验 `quote` 是子串、`speaker` 取事件 → 填 `session_id`/`event_sha256`。失败即拒绝。`delegationDepthOf(agent) > 0` 时写工具不注册。

### 5.4 三档权限

T0（可信新增 + 全等去重，受扫描与 `quota.t0_per_session`）、T1（推断/修订/替代/合并/拆分/删除，只提案）、T2（改 SOUL/USER/RULES/policy、purge、存储权限，无模型工具）。

## 6. 关键机制

### 6.1 注入与会话快照

- 四段固定区；用 `ctx.systemPrompt.section({ name:'agent-memory', order, text, interpolate:false })`；**文本由 core 按 session 冻结**（DSH 每轮重渲染）。
- 预算：`ctx.tokenMeter.estimateMessage` 对合成 system 消息定价；不可用则 `chars ÷ 2.5` 粗估并标"估算"；两值都记录。初始字符上限沿用 S1：200 / 1500 / 800 / 1200，合计 3700。
- RULES 超预算 → 装配预检失败（退出码 2），不截断；目录超预算按 §4.4 裁剪。
- 转义：四段与召回结果用随机 16 hex 分隔符 + JSON 包装；正文含 ``` / `</memory>` 不逃逸。
- 快照：`.state/snapshots/<sha256(session_id)[0..32]>.json`；键 = session + `memory_revision` + `prompt_schema_version`；保留 30 天或最近 50 个；`purge` 可清。
- 重启续接从快照恢复；缺失重捕获并写审计；目录冻结但 `recall` 实时可见（README 写明）。

### 6.2 写入事务与恢复（Windows 版）

1. 取锁（读之前；覆盖读—校验—写—台账—派生物全程）；
2. 读 + 校验（含 `base_hash`）；
3. 写 `.state/txn/<op_id>.json`；
4. 写临时文件 → **`fs.fsync(fd)`** → `fs.rename`（Windows 上 rename 若 `EPERM`/`EBUSY`，有限退避重试）；
5. 追加 ledger（`{id, sha256, op_id, at, prev}`，op_id 幂等）；
6. 追加 audit（失败不阻断，ledger 兜底）；
7. 重建 MEMORY.md + manifest（manifest 记 `ledger_head`）；
8. 删 txn、释放锁。

**持久化口径**：Windows 无法对目录 `FlushFileBuffers`，所以"rename 返回"不保证目录项已落盘。V1 承诺的是：**崩溃后可检测、可恢复、不静默丢数据**；不承诺断电零丢失。README 明写。恢复时 txn + ledger + 文件哈希三方对账；对不上就阻断写入并点名。

**锁**：租约含 PID + 启动时间 + 心跳；陈旧 = 心跳超时 **且** PID 不存活，默认 5 分钟；获取超时 60 秒报错。

### 6.3 召回

- S2a 先做**子串召回**（abstract+正文，大小写不敏感），只为验证 store→index→recall 链路；S3 换成 BM25。
- 分词：NFKC + 小写；CJK 二元组；ASCII 词；代码型片段整体保留并拆分；`tokenizer_version` 进 manifest。
- 打分：BM25（k1=1.2，b=0.75），`error_signatures` ×4、`abstract` ×3、正文 ×1；字面命中独立加分。
- 未找到：低于 `recall.min_score` 或匹配占比不足 → 空结果 + 明确"未找到"。
- 评估：fixture 200 条 + **dev 30 查询 / held-out 10 查询**；指标 Recall@5、per-kind Recall@5、无答案误返回、p95、冷启动、常驻内存；门槛只升不降（首次基线写 ADR）。
- 中文分词选择：二元组 vs `Intl.Segmenter` 用 dev 集对比；**不引 jieba**（零依赖 + 词典漂移）。外部资料（未核验）见附录 C。

### 6.4 扫描（不可关闭）

不可见/双向 Unicode 硬拒；密钥特征硬拒（尽力而为）；注入模式拒绝或降提案；`<private>` 不静默剥离（T0 拒绝、T1 提案带脱敏文本）。拒绝记录只含规则 ID 与字段名。`adopt` 同样过扫描。

### 6.5 失败姿态与退出码

同 v1.1：全局错误响亮（2）；单条损坏/未入账隔离（doctor 4）；派生物重建（0）；锁超时（2）；用法错误（1）。补一条：**ENOSPC/EACCES 失败要清理临时文件并点名路径**，不留半写。

### 6.6 边界与篡改检测

- 实测：写被 fence、读不被 fence；插件进程不受限。只宣称"模型工具没有写入口 + 篡改可检测"。
- `ledger.jsonl` 不轮转，哈希不在台账 → 隔离，直到 `mem adopt`。
- `SOUL/USER/RULES` 规范化哈希并入封存（去 BOM、LF、单个结尾换行）。
- manifest 的 `ledger_head` 是 tripwire：台账被截断/断链 → doctor 报 4；manifest 可重建但 tripwire 只能报警不能自愈（明确）。
- 已知局限：同权限进程可同时改文件与台账；要更强需独立 Windows 身份 + 窄 IPC，V1 不做。
- `mem init` 把 `<home>` ACL 收紧到当前用户 + SYSTEM（失败警告不阻断）。

---

## 7. 收尾蒸馏

- L0 确定性打标（重复错误、纠正语、工具失败后成功、回滚），产出事件引用。
- `/closeout` 命令 → 注册 `closeout_submit`（仅本轮）→ `agent.followup({content, source})` → `await whenIdle()` → **dispose**（成功、失败、超时都 dispose）。
- 提示词含 L0 清单 + JSON Schema 契约；模型用 `closeout_submit` 回应；解析失败 → "本次未产出可解析提案"，不自动重试。
- 硬校验：证据可核验、模型自己的助手消息不算证据、与 RULES/活动/待审/已否决去重、≤5 条、无内容明说、只有 `decide` 采纳才写入、失败保留提案。
- 决定界面 `mem proposals` / `mem decide --batch`；代价是模型估计。

  readonly event_seq: number;

  readonly evidence_level: EvidenceLevel;
  readonly error_signatures: readonly string[];
  readonly provenance: readonly ProvenanceEntry[];
  readonly body: string;
  readonly file_path: string;      // server-derived

  readonly kind: Kind;
  readonly abstract: string;
  readonly body: string;
  readonly valid_from?: string;
  readonly error_signatures?: readonly string[];
  readonly evidence_level: Exclude<EvidenceLevel, 'inferred'>;

export type ProposalInput =
  | { readonly op: 'revise'; readonly target: MemoryId; readonly base_hash: string; readonly patch: { abstract?: string; body?: string } }
  | { readonly op: 'supersede'; readonly target: MemoryId; readonly base_hash: string; readonly replacement: RecordInput }
  | { readonly op: 'merge'; readonly targets: readonly MemoryId[]; readonly base_hashes: readonly string[]; readonly merged: RecordInput }
  | { readonly op: 'split'; readonly target: MemoryId; readonly base_hash: string; readonly parts: readonly RecordInput[] }

## 附录 G：术语表

| 术语 | 含义 |
|---|---|
| 记忆文件 | `memories/<kind>/<id>.md`，权威数据，创建后不可变 |
| 目录（MEMORY.md） | 派生视图，一行一条，可重建 |

| 审计（audit） | `audit.jsonl`，人类可读轨迹，可轮转可关闭 |
| 账本（decisions） | `proposals/decisions.jsonl`，采纳/否决/删除决定，第二真相源 |
| 提案 | 待人决定的候选，存 `proposals/pending/` |
| 隔离 | 未入账/损坏文件，不进索引、召回、注入 |
| 快照 | 会话冻结的注入文本，存 `.state/snapshots/` |
