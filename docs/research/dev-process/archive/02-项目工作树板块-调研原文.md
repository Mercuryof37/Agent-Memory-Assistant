# 项目工作树板块：开发流程借鉴（大厂与 AI 公司开源实践）

> 范围：本板块对应「项目工作树」——项目总览（L0）→ 项目树/记忆列表（L1）→ 焦点局部关系图（L2），以及支撑它的 `projects.json`、记录的 `project`/`tags`/`relations` 字段和 `/api/agent-memory/graph|projects|item` 契约。
> 目标：把外部团队在**语义设计、契约测试、UI 验证、迁移与性能预算**上的流程做法，落成本板块的门禁与检查单。

## 1. 外部流程要点

### 1.1 新"API surface"先走提案，再写实现

- React 的 RFC 流程把"新增 API 面"列为必须 RFC 的典型场景，理由是新 API 一旦发布就要长期维护；社区 RFC 大多数不会合并，但讨论本身会被后续设计吸收（[React RFCs](https://github.com/reactjs/rfcs/blob/main/README.md)）。
- Kubernetes 的 KEP 要求新特性/大改动先提案，并配明确的 approver/reviewer 与结构化记录（[KEPs](https://github.com/kubernetes/enhancements/blob/master/keps/README.md)）。
- LLVM 要求"会改变语言参考"的变更先 RFC，评审者也可要求先达成 RFC 共识（[CodeReview](https://github.com/llvm/llvm-project/blob/main/llvm/docs/CodeReview.md)）。
- 对本板块的含义：关系方向（`relates_to`/`derived_from`）、传递性、跨项目限制、删除项目后的归属、图的范围，都是"API surface"级语义，应先有书面设计。

### 1.2 契约先行，测试要能防止"接口悄悄漂移"

- Microsoft 的工程手册把消费者驱动契约测试（CDC）列为验证"消费者与提供者共享同一份契约"的手段，并把集成/E2E 与单测分层（[automated-testing](https://github.com/microsoft/code-with-engineering-playbook/blob/main/docs/automated-testing/README.md)）。
- Google 的评审清单提醒：涉及用户可见行为的改动，光读代码很难判断影响，应当让作者演示或自己跑一遍（[looking-for](https://github.com/google/eng-practices/blob/master/review/reviewer/looking-for.md)）。
- 对本板块的含义：`packages/dsh/src/gui.ts` 的路由表就是契约；每条路由的入参、返回、错误码应有快照用例，否则客户端与宿主会各自漂移。

### 1.3 UI 改动要有"看得见"的证据

- Google 明确：UI 类变更最好由作者演示，或评审者自己运行验证（同上）。
- Microsoft 把可访问性列为非功能需求，并要求 UI 测试覆盖"用户能否操作界面"（[automated-testing](https://github.com/microsoft/code-with-engineering-playbook/blob/main/docs/automated-testing/README.md)、[accessibility](https://github.com/microsoft/code-with-engineering-playbook/blob/main/docs/non-functional-requirements/accessibility.md)）。
- 对本板块的含义：图/树的变更至少要附截图或录屏，覆盖空态、单项目、多项目、大图、窄窗口；不能只用"逻辑测试通过"当验收。

### 1.4 数据迁移与兼容要显式

- vLLM 的弃用策略把"字段/配置/API"的移除拆成三段式并绑定 minor 版本，禁止在 patch 里删除（[deprecation_policy](https://github.com/vllm-project/vllm/blob/main/docs/contributing/deprecation_policy.md)）。
- Anthropic 的仓库要求破坏性变更保留别名、走弃用周期，并用脚本对比基线检测公开符号删除（[CLAUDE.md](https://github.com/anthropics/anthropic-sdk-python/blob/main/CLAUDE.md)）。
- 对本板块的含义：`project`/`tags`/`relations` 从 v1.3 到 v1.4 有"缺省读成未归类/空关系"的兼容规则，这个规则必须有测试锁住；未来再加字段同理。

### 1.5 性能与规模要有预算，不靠"感觉很快"

- Microsoft 的测试手册把负载/性能测试列为常规验证手段（[automated-testing](https://github.com/microsoft/code-with-engineering-playbook/blob/main/docs/automated-testing/README.md)）。
- Kubernetes 的 PR 流程要求本地跑 `make verify` / `make test` / `make test-integration` 预判 CI（[pull-requests](https://github.com/kubernetes/community/blob/master/contributors/guide/pull-requests.md)）。
- 对本板块的含义：局部图要有节点上限与降级策略（超过阈值折叠/只显示一跳），并在 PR 里给出大项目的渲染耗时数据。

### 1.6 回滚优先于"边跑边修"

- LLVM 鼓励 post-commit review，并允许因重大疑问要求**及时回滚**，让设计讨论不阻塞主干（[CodeReview](https://github.com/llvm/llvm-project/blob/main/llvm/docs/CodeReview.md)）。
- 对本板块的含义：图/树的数据结构或投影出错时，先回滚到上一版，再讨论；不要在主干上热修数据投影。

## 2. 对本板块的启示（现状 → 该补的流程）

| 现状 | 流程缺口 | 借鉴 |
|---|---|---|
| 有 L0–L2 工作树与局部图（ADR-0038） | 关系语义没有单独的"设计稿"沉淀 | React RFC/KEP |
| `gui.ts` 有 17 条路由 | 没有契约快照测试 | Microsoft CDC |
| 有 UI 规范（中文命名、编号） | 没有"UI 改动必须附截图/空态"的流程 | Google looking-for |
| `project`/`tags`/`relations` 有缺省兼容 | 兼容规则没有专门测试锁定 | vLLM/Anthropic |
| 图渲染无明确上限 | 缺性能预算与降级策略 | Microsoft 性能测试 |
| 支持删除项目（记忆回到未归类） | 删除的边界（不删记忆、图如何变）缺少负向用例 | Anthropic REVIEW.md |

## 3. 建议流程（五步）

1. **语义提案（RFC 级）**：涉及关系方向/传递性/跨项目限制/删除归属/图范围的改动，先写一页设计：定义、例子、反例、兼容、回滚。产物：ADR 或 `docs/plan/` 下的设计稿。
2. **契约与用例先行**：先改 `gui.ts` 路由表与返回类型，补契约快照（路径、入参、返回、错误码）；再补图算法单测（循环、自引用、跨项目拒绝、孤立节点、删除项目）。
3. **实现（小步）**：关系读写、图投影、客户端渲染分开提交；客户端只依赖契约，不直接读文件（架构硬约束）。
4. **UI 验收**：截图/录屏四件套——空态、单项目、多项目、大图（或窄屏）；检查键盘可达、对比度、中文命名与编号规范；大图给出耗时与降级结果。
5. **发布与回滚**：新图模式默认关闭或仅内部可见；灰度到真实项目；出问题回滚到旧投影，数据不动。

## 4. 门禁与验收（可直接转成测试/检查单）

- [ ] 关系语义改动有 ADR/设计稿，含"例子 + 反例 + 兼容 + 回滚"。
- [ ] 每条新路由/字段有契约快照测试；错误码（400/404/409）有负向用例。
- [ ] 图算法用例覆盖：自引用拒绝、跨项目拒绝、循环处理、孤立节点、删除项目后回到未归类。
- [ ] 旧记录（无 `project`/`relations`）读成未归类/空关系，且不会被静默写回。
- [ ] 大项目（如 1000 条）局部图渲染在预算内，超阈值有降级。
- [ ] UI 改动附截图/录屏，覆盖空态与窄屏。
- [ ] 删除项目不删除记忆，journal 有审计行。

## 5. 反模式

- 只改后端图算法，不做 UI 验证就宣布"工作树完成"。
- 图数据结构与 API 契约在同一次大提交里重构，出问题无法定位。
- 为了让图"好看"而自动合并相似节点（产品已明确不自动合并，流程上也不要加）。
- 删除项目时顺手删记忆（边界被破坏，且不可逆）。
- 用截图代替契约测试，或用契约测试代替 UI 验收。
