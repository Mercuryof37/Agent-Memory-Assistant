# 记忆板块：可写入记忆的条目

> 用法：在「记忆 → 手写新增」里逐条录入；类型选“经验”或“事实”，摘要填一句话，正文填正文。
> 限制：摘要默认 ≤120 字，正文 ≤4000 字；本组不含“坑”，避免为流程经验硬编错误特征。
> 说明：这些是从外部开发流程调研提炼的经验，没有 DSH 会话事件可引用，请按人工新增录入，不要编造 evidence。

## 1

- 类型：经验
- 摘要：改记忆数据格式或召回算法前先写 ADR，写清兼容与回滚
- 正文：先列出影响面（字段、算法、提案、注入）、旧记录怎么读、失败时怎么退、回滚到哪个版本；缺任一项不进入实现。纯 UI 与文案改动不需要这一步。大厂把这类变更当 RFC 级：先有文档，再有代码。

## 2

- 类型：经验
- 摘要：修记忆缺陷先写“修复前失败”的用例，再改到通过
- 正文：同一测试文件里保留失败复现与通过用例，证明修复真的改变了行为；坏 frontmatter、坏证据、坏关系、越权来源等拒绝路径各留一个 [neg] 用例。只测“能存能读”不算完成。

## 3

- 类型：经验
- 摘要：采纳提案前校验 base_hash，过期就拒绝并保留待审文件
- 正文：补一条负向用例：先改记录、再采纳旧提案，必须被拒且提案仍在 pending/。不做静默覆盖，也不自动合并相似条目；拒绝时点名 base_hash，而不是笼统报错。

## 4

- 类型：事实
- 摘要：记忆写入只有一个入口：store 的校验、锁与 journal
- 正文：GUI、CLI、MCP 都调用 core 的服务，不复制写入逻辑；删除只写 journal，不写回旧文件。直接改 memories/ 文件不会被当作正常写入，doctor 能发现不一致。

## 5

- 类型：经验
- 摘要：删字段、工具或命令走“标记 → 默认关闭 → 移除”，补丁版本不删
- 正文：每一步给出移除版本与替代路径；旧 mem_schema 记录继续可读，不静默重写。发布说明写清 removals，补丁版本不删功能。

## 6

- 类型：经验
- 摘要：记忆或索引变更出问题先回滚，再在 ADR 或 issue 里讨论
- 正文：不在主干边跑边修；回滚后补失败用例，再重新提交。回滚不是失败，是让讨论不阻塞其他人的常规手段，回滚后再补设计说明。
