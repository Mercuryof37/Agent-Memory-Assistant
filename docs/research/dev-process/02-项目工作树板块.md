# 项目工作树板块：可写入记忆的条目

> 用法：在「记忆 → 手写新增」里逐条录入；类型选“经验”或“事实”。
> 限制：摘要默认 ≤120 字，正文 ≤4000 字；本组不含“坑”，避免为流程经验硬编错误特征。
> 说明：这些是从外部开发流程调研提炼的经验，没有 DSH 会话事件可引用，请按人工新增录入，不要编造 evidence。

## 1

- 类型：经验
- 摘要：改关系方向、传递性或跨项目限制前，先写一页设计
- 正文：设计里给出定义、例子、反例、兼容与回滚；关系属于对外语义，要先覆盖自引用、循环、删除项目后的归属，再写实现。只改算法不改文档，下次还会出现歧义。

## 2

- 类型：经验
- 摘要：改 /api/agent-memory/* 时同步更新契约快照
- 正文：契约包含路径、入参、返回与错误码；客户端只依赖契约，不直接读文件。400、404、409 各留一个负向用例，避免客户端与宿主各自漂移。

## 3

- 类型：经验
- 摘要：图或树的改动必须附截图或录屏，覆盖空态、单项目、多项目、大图、窄屏
- 正文：逻辑测试不能代替 UI 验收；同时检查键盘可达、对比度与中文命名规范。只写“逻辑测试通过”不算完成，截图或录屏要覆盖空态与窄屏。

## 4

- 类型：经验
- 摘要：局部图设节点上限，超阈值折叠或只显示一跳，并给出耗时
- 正文：按大项目（约 1000 条记忆）估算；降级是产品行为，不是异常。改动在 PR 里附渲染耗时，超过阈值就折叠或只显示一跳，保证大项目仍可操作。

## 5

- 类型：事实
- 摘要：删除项目不删记忆，记忆退回“未归类”，journal 留审计
- 正文：负向用例：删除项目后记忆仍可读，图里不再出现该项目节点；审计行不含正文。删除项目是归类变化，不是删除记忆。

## 6

- 类型：经验
- 摘要：旧记录缺 project、tags、relations 时读成未归类或空关系，且不写回
- 正文：兼容规则用测试锁住；以后新增字段照此办理，旧记录不被静默重写。读的时候补默认值，写的时候不回头改旧文件。
