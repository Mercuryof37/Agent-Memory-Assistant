# Agent Memory V1.0 开发方案（优化版）

> **已被取代**：本文件是历史版本，现行方案是 [V1.0-开发方案-最优版-v1.1.md](../V1.0-开发方案-最优版-v1.1.md)（仓库根目录同名文件在 docs/research 下）。


> **修订日期**：2026-10-17  
> **目标运行环境**：Windows、本地 NTFS、Node.js 24、DeepSeek Harness（DSH；实现前锁定具体版本与 lockfile）  
> **目标目录**：`D:\Ai Agent\Agent Memory`  
> **产品边界**：先服务单机 DSH；Markdown 是可读的记忆源文件；不依赖云端记忆服务。  
> **工期估算**：全量 V1 约 21–25 人日，单人约 4–5 周；不含 DSH 版本变化造成的返工。估算包含集成验证与验收，不等于承诺工期。

## 0. 本轮优化结论

这份方案的核心方向保留：源文件可读、索引可重建、记忆带来源、相似内容不自动合并、删除须人工确认。为降低 V1 的实现风险，按以下决定执行：

1. **先做 DSH 兼容性验证，再承诺注入与快照设计。** DSH 的扩展点、会话事件、系统提示词和压缩行为随版本演进。以实际安装的精确版本和公开 API 为准；`appendPluginRecord` 等内部或实验接口未经该版本官方支持，不作为产品依赖。
2. **安全边界按进程权限描述。** 记忆放在工作区外只改变路径，不自动形成权限隔离。只有 DSH 的工具沙箱或独立服务进程/操作系统身份确实阻断直读直写时，才宣称文件系统级保护；否则 V1 的边界只是“模型工具没有任意文件写入口”。
3. **原始会话留在 DSH 自己的会话存储中。** 记忆只保存可验证的会话/事件引用、说话人、序号和必要短引文；不默认再复制整段对话。蒸馏只在用户明确触发后提出候选，采纳后才进入活动记忆。
4. **把模型指引与机器门禁分开。** 提示词里写“必须”不等于系统能强制执行。只有权限检查、数据校验或可验证测试落实的条目才标为机器门禁；其余标为模型指引。
5. **用真实 token 预算控制注入。** 字符数不能稳定换算为 token，3700 个中英文字符不能承诺约 1200 token。优先使用当前模型/DSH 可用的 token 计量；不可用时用保守字符上限并标记为估算。
6. **先以词法检索满足几百条规模。** 用固定查询集衡量召回与误召回；若达不到目标，再评估 FTS5 或向量检索。暂不为未验证的 v1.2 提前建设多后端抽象、空 MCP 包和付费空钩子。

## 1. V1.0 的用户可见结果

| 能力 | V1.0 交付标准 |
|---|---|
| 记忆存取 | 人可以直接阅读 Markdown；服务端可新增、读取、检索、重建索引；损坏时指出具体文件和恢复办法 |
| 新会话注入 | 注入人格/偏好/规则摘要和受预算限制的目录；同一 DSH 会话重放同一快照 |
| 记忆写入 | 每条活动记忆带来源、时间和作用范围；写入走服务接口；低风险操作可回滚 |
| 审批 | 相似合并、矛盾修订、删除等只生成待审提案；只有人类审批入口能采纳/否决 |
| 蒸馏 | 用户手动触发；每条候选能回到原会话证据；无内容时明确返回“本次无新提案” |
| 维护 | CLI 提供 `doctor`、`rebuild`、`proposals`、`decide`、`export`、`purge`；V1 不含 Web 编辑器 |

### 明确不承诺

- 规则文本不能保证模型在所有回答中服从；权限和安全必须由服务端/宿主实现。
- 正则扫描不能证明内容里没有密钥，也不能可靠识别所有提示词注入。
- 稳定提示词有助于复用缓存前缀，但缓存命中由模型提供方、路由和请求内容决定，不能保证节省金额或延迟。
- “几百条记忆检索可用”必须以本项目固定查询集验证，不能仅由条目数推断。

## 2. 范围与版本切分

### 2.1 V1.0 实现

| 模块 | 交付内容 |
|---|---|
| Core | schema、Markdown 存储、有效期/替代关系、词法检索、可重建索引、追加审计、权限策略 |
| DSH adapter | 注册只读/写入工具；稳定会话快照；用户审批入口；仅使用锁定版本支持的 API |
| CLI | 初始化、诊断、重建、查看提案、审批/否决、备份导出和按 ID 清除 |
| Closeout | 人工触发的候选生成；最多 5 条；引用原始 DSH 会话事件；逐条决定 |
| 安全 | 输入校验、敏感内容检测（尽力而为）、本地路径限制、失败关闭、审计最小化 |

### 2.2 延后至 V1.1 或有真实需求时

Web 查看器、MCP server、跨设备同步、多租户、计费/权益、自动后台整合、自动删除、自动生成 strategy、向量索引、完整原始会话副本、空接口包和空付费钩子。Core 可保持普通 TypeScript 接口，但不为暂未实现的客户端预建包。

## 3. 架构

### 3.1 依赖方向

```text
packages/core   纯领域逻辑与存储接口；不依赖 DSH
packages/dsh    DSH 插件适配；只调用 core service，不直接操作记忆文件
packages/cli    本地维护命令；与 DSH 使用同一 service 和 policy
```

所有包使用同一套 schema、服务和策略。构建检查禁止 `core` 导入 `@deepseek-ai/*`，禁止 `dsh` 绕过 service 直接读写记忆目录。CLI 也不得复制一套独立写入逻辑。

### 3.2 技术选择

| 领域 | V1 选择 | 约束与退出条件 |
|---|---|---|
| Runtime | 锁定 Node 24 的精确补丁版本与 DSH 版本；提交 lockfile | DSH 升级须跑兼容性验收；不以“Node 24”大版本代替精确版本 |
| 语言/构建 | TypeScript strict；esbuild 仅在 DSH 构建链需要时使用 | 避免额外构建层；以实际加载方式为准 |
| 测试 | `node:test`，不增加测试框架依赖 | 测试清单见第 9 节 |
| 权威存储 | 每条记忆一份 Markdown 文件 | 读取/检索以文件为准；不把索引或缓存当真相 |
| 元数据 | YAML frontmatter 仅允许 schema 中列出的字段；使用成熟解析器，禁用自定义 tag/alias 等能力 | 若坚持零依赖，则改为 JSON 元数据块并用 `JSON.parse`；不要自研“部分 YAML”解析器 |
| 检索 | 小规模本地词法评分；metadata 过滤；按稳定规则排序 | 先用验收查询集测 Recall@5、Precision@5 与误召回；持续达标才保留轻实现 |
| 索引 | 初始只缓存可重建的 manifest/词项统计；缓存原子替换 | 索引缺失/版本不符时自动重建；几百条规模若重建耗时可忽略，不保存重复全文索引 |
| 审计 | 追加 JSONL，记录操作 ID、操作者类别、条目 ID、结果、时间和来源引用 | 不记原始密钥、完整正文或完整会话；轮转/备份与损坏检测写入运维说明 |
| 并发 | 本地文件系统独占锁；锁覆盖读、校验、写入与审计提交 | 只支持经验证的本地 NTFS；不宣称网络盘安全。锁超时必须报错，不静默覆盖 |

**SQLite 判断**：当前 Node 24 文档将 `node:sqlite` 标为 Release Candidate。若将来需要 FTS5/事务，再评估锁定 Node 补丁版本、SQLite 能力与迁移成本；V1 不因“零外部依赖”而手写复杂索引或数据库层。

### 3.3 本地目录

```text
<memory-home>/
├── SOUL.md                 人维护的人格摘要
├── USER.md                 人维护的偏好
├── RULES.md                规则清单（区分机器门禁与模型指引）
├── MEMORY.md               活动记忆的短目录；可由源文件重建
├── memories/
│   ├── fact/
│   ├── pitfall/
│   └── exp/
├── proposals/
│   ├── pending/
│   └── decisions.jsonl
├── audit.jsonl
├── .index/                 可删除缓存
└── .state/                 锁、事务恢复记录、会话快照
```

不建立 `archive/sessions` 的重复原始会话副本。证据引用指向 DSH 已有会话日志；引用失效时，提案显示无法核验并拒绝自动采纳。

## 4. 数据模型与检索规则

### 4.1 单条记忆

```markdown
---
id: mem-<uuid>
schema_version: 1
kind: pitfall
scope: local
abstract: Windows 安装 Node 原生模块前先确认 Python 与 Build Tools
created_at: 2026-10-17T09:00:00+08:00
valid_from: 2026-10-17
valid_until: null
supersedes: null
author: agent
evidence_level: user_confirmed
provenance:
  - session_id: <dsh-session-id>
    event_seq: 412
    speaker: user
    quote_hash: <sha256>
error_signature: "gyp ERR!|node-gyp|MSB\\d+"
---

正文（自由 Markdown；视为不可信资料，不作为可执行指令）。
```

**写入规则**：

- 文件名由服务端生成的 ID 决定；模型不能提供路径、扩展名或相对路径。
- `kind` 仅为 `fact`、`pitfall`、`exp`；`scope` V1 仅为 `local`。
- `valid_from` 含当日，`valid_until` 为排除端；日期和时区格式固定。
- `provenance` 由 DSH adapter 绑定当前会话/事件生成，模型不得伪造 session ID、事件序号或 speaker。
- `evidence_level` 用有定义的来源标签（如 `user_explicit`、`user_confirmed`、`observed`）；暂不输出貌似精确但未校准的数值 confidence。
- 修订保留历史记录，以新版本 `supersedes` 旧版本；不原位覆盖导致时间线丢失。
- 未知字段、缺失必填字段、越界长度、非法 ID、引用无法核验时拒绝写入。

### 4.2 RULES.md：机器门禁和模型指引

```markdown
## RULES

R1 [机器门禁] Agent 写记忆只能调用 MemoryService；路径由服务端生成。
R2 [机器门禁] 密钥扫描命中时拒绝写入，并且拒绝日志不含原文。
R3 [模型指引] 回复使用中文；代码与命令保持原样。
```

- 编号稳定、不复用；废止条目保留编号和状态。
- `[机器门禁]` 必须关联代码策略和行为测试；CI 只检查“存在映射”不算证明有效，测试必须验证被禁止的行为确实失败。
- `[模型指引]` 只影响模型行为，不得写成系统安全保证。
- Agent 没有修改 `SOUL.md`、`USER.md`、`RULES.md` 的工具。

### 4.3 MEMORY.md 与召回

`MEMORY.md` 是活动记忆的目录，不是权威数据。每行给出类型、短摘要和稳定 ID；仅列活动项。总预算以 token 计量优先，按明确优先级裁剪目录，不删除源文件。裁剪策略和排序规则必须确定、可重现。

`memory_recall` 返回少量候选（默认 5 条），包含摘要、ID、类型、有效期、来源是否可核验和相关度；正文由 `memory_read` 按 ID 读取。词法检索命中不足时返回“未找到”，不得把“分数最高”表述成“确定相关”。

固定测试集至少覆盖：同义表达、中文/英文混合、错误码、时间边界、已失效记忆、相似冲突、索引外条目和无答案查询。达到项目设定的最低 Recall@5 且误召回率可接受后，才冻结词法方案。

## 5. 服务接口与权限

### 5.1 MemoryService

```ts
interface MemoryService {
  recall(q: RecallQuery): Promise<Hit[]>;
  read(id: MemoryId): Promise<MemoryDoc>;
  asOf(q: RecallQuery, date: string): Promise<Hit[]>;
  rules(): Promise<Rule[]>;
  stats(): Promise<Stats>;

  // 仅新增低风险、带可信来源的记录；路径和 provenance 由服务生成
  record(input: RecordInput, actor: TrustedActorContext): Promise<WriteResult>;

  // 冲突修订、相似合并、拆分、删除只入待审批账本
  propose(input: ProposalInput, actor: TrustedActorContext): Promise<Proposal>;
  decide(id: ProposalId, decision: 'accept' | 'reject', approver: HumanApprovalContext): Promise<void>;
}
```

`TrustedActorContext` 由宿主适配层构造，不接受模型工具参数覆盖。`decide` 只供真实的人类审批入口/CLI 使用，不注册为模型可调用工具。采纳提案前重新读取目标条目和引用，检查版本/hash 未变化；过期提案要求重新生成。

### 5.2 模型工具

| 工具 | 权限 | 说明 |
|---|---|---|
| `memory_recall` | 读 | 搜索活动记忆；可选 `as_of` |
| `memory_read` | 读 | 按服务生成的 ID 读正文 |
| `memory_record` | T0 | 新增符合证据与隐私规则的低风险条目 |
| `memory_propose` | T1 | 提交修改、替代、合并、拆分或删除建议 |
| `rules_list` | 读 | 列出规则和执行类别 |
| `closeout` | T1 | 人工触发候选蒸馏，不直接改活动记忆 |

模型工具不暴露任意路径、整文件覆盖、批量删除、批准/否决、改规则或清空接口。所有入口（工具和 CLI）调用相同 service。

### 5.3 T0/T1/T2

| 档位 | 动作 | 规则 |
|---|---|---|
| T0 | 有可信来源的低风险新增；完全相同内容去重 | 可回滚；需来源和配额校验；相似不等于相同 |
| T1 | 推断性/矛盾内容、修订、替代、相似合并、拆分、删除 | 只能提案；人类审批后服务端重新校验并提交 |
| T2 | 改 SOUL/USER/RULES、清空/物理清理、变更存储权限 | 无模型工具；由人维护或受控 CLI 执行 |

字节级完全相同去重也不能改变既有内容或删除证据；只可附加引用或返回既有 ID。相似度命中只提示候选，不自动合并。

## 6. DSH 注入、会话快照与安全

### 6.1 注入和快照

- 注入固定区：SOUL 摘要、USER 偏好、规则、有限活动记忆目录。正文按需召回，不常驻。
- 快照键至少包含 DSH session ID、memory revision 和 prompt schema 版本。每次 DSH prompt assembly 对同一 session 返回同一快照；新 session 才捕获新版本。
- DSH 当前公开文档描述系统提示词作为历史中的 system 节点；当前压缩实现保护该节点。目标版本未必相同，S0 必须对锁定版本实测：新建、续接、重启续接、压缩、提示词更新、空记忆。
- 通过该版本正式支持的持久化接口保存/恢复快照。若没有外部插件可用的持久化接口，优先使用本地受限 session snapshot 文件并绑定 session ID；不要调用仅供仓库内部实验包使用的 `appendPluginRecord`。
- 预算按 token 计量；预留模型系统提示词和工具 schema 空间。硬规则不因裁剪被静默截断；预算不足时显式报错或缩短非强制目录。
- 缓存效果只作为性能指标观测，不作为正确性条件或收益承诺。

### 6.2 安全与隐私

| 风险 | V1 处理 |
|---|---|
| 路径穿越/任意覆盖 | 服务端生成 ID 和路径；规范化后验证仍在根目录内；拒绝符号链接/重解析点逃逸；仅允许固定字段 |
| 并发/崩溃 | 独占锁；原子替换；操作 ID + 恢复记录；启动时恢复或明确报错；索引可全量重建 |
| 敏感信息 | 对常见密钥格式做尽力检测并拒绝；不记录命中原文；检测不是“绝无秘密”的保证 |
| 隐形/双向字符 | 拒绝不可见控制字符或在 UI 中明确展示；保留可审计拒绝原因 |
| 私密标记 | 不静默删掉 `<private>` 内容；拒绝该候选或由用户确认后生成带明确标记的脱敏文本 |
| 记忆中的指令 | 召回内容作为引用资料呈现并标来源；不能覆盖系统/开发者策略或授权边界；服务端授权不依据记忆正文 |
| 会话原文 | 不复制完整轨迹；提案存必要短引文和事件引用；提供备份、按 ID 清除和保留策略 |
| 本地 Web 风险 | V1 不提供 Web 服务；如后续加入，只绑定 localhost、转义渲染内容且默认只读 |

### 6.3 文件权限的真实边界

S0 要验证 DSH shell、文件工具、子 agent 和插件是否共享同一 Windows 用户权限。目录位于工作区之外并不使 DSH 进程无法读取。如果工具沙箱不能限制这些路径，文档必须把“防直接文件写入”降级为工具层策略；要获得 OS 级隔离，须由独立身份运行记忆服务并通过窄 IPC 暴露允许操作。V1 不以提示词或目录命名冒充安全边界。

## 7. 收尾蒸馏

1. 只能由用户显式触发；V1 不在每次会话结束时后台自动调用模型。
2. 从 DSH 会话事件中找错误、明确纠正、重复失败或明确决策；只取必要事件，不把整份轨迹复制到记忆目录。
3. 产出最多 5 条候选，每条包含类型、摘要、原始 speaker、session/event 序号、短引文或可核验引用、有效范围及可能的副作用。
4. 无来源、来源不是用户/工具事实、与当前规则冲突、包含明显秘密、超过预算或引用无法核验时拒绝或降为人工检查。
5. `rule` 类候选必须附机器检查设计；若当前无法机器验证，改为模型指引或 pitfall，不宣称硬约束。
6. 与活动记忆、待审提案和已否决条目去重；否决记录只保留摘要哈希、原因类别和来源 ID，避免再存敏感原文。
7. 只有经 `decide` 人工确认的候选才写入活动存储；失败时保留提案，不部分提交。

## 8. 实施阶段与估时

| 阶段 | 目标与交付 | 验收重点 | 估时 |
|---|---|---|---:|
| S0 兼容性 Spike | 锁定 DSH/Node 版本；验证注册工具、prompt assembly、会话 ID、重启恢复、压缩、审批 UI 和沙箱边界 | 记录精确 API/事件；插件能装载；确认哪些保证成立，哪些不能成立 | 2–3 天 |
| S1 工程骨架 | workspace、strict TS、配置 schema、日志与最小 CLI | 未知配置拒绝；core 不依赖 DSH；包边界检查通过 | 2 天 |
| S2 存储与模型 | schema、safe ID、原子写、锁、有效期、替代链、审计/恢复、重建 | 中断写入不破坏已提交文件；损坏可诊断；重建结果一致 | 4–5 天 |
| S3 召回与注入 | 词法排名、固定查询集、token 预算、会话快照 | 同 session 稳定；重启续接一致；压缩后系统区行为符合目标 DSH 版本 | 3–4 天 |
| S4 工具与审批 | 读/写/提案工具、T0/T1/T2、审批入口 | 模型不能批准提案、改规则、任意写路径或跨 session 伪造来源 | 4–5 天 |
| S5 收尾与运维 | 手动 closeout、doctor/export/purge、备份说明 | 无引用不能采纳；无候选不凑数；导出和删除按 ID 验收 | 3–4 天 |
| S6 发布门禁 | 锁文件、发布包、恢复演练、阶段决策记录 | 从干净环境安装；关键路径可演示；回滚/备份可恢复 | 3–4 天 |

总计约 21–25 人日。若 S0 发现目标 DSH 版本没有所需的官方扩展能力，先缩减功能或升级 DSH；不要把未验证的内部 API 计入剩余阶段估时。

## 9. 验收与 CI

### 9.1 必须通过的行为验收

- 删除 `.index` 后重建，活动条目、有效期和检索结果与源文件一致。
- 并发写冲突时第二笔明确失败，第一笔数据保持完整；锁超时后无静默覆盖。
- 写入进程在每个提交步骤被中断，重启后由恢复记录完成提交或报告待修复状态；不产生“内容已写但审计误报成功”。
- 未知字段、未知配置键、路径穿越、符号链接逃逸、非法日期和过长输入均拒绝。
- `valid_until` 前后边界、`as_of`、替代条目和历史版本均按约定返回。
- 记录不可见字符/密钥检测命中；拒绝日志不泄露被拒内容。
- 提案引用必须能回到 DSH 事件；过期目标被修改后不能直接采纳。
- 模型工具调用 `decide`、任意文件写、修改 RULES、删除活动条目均失败。
- 同 session 快照在新轮次、压缩、进程重启续接后稳定；新 session 能看到更新后的记忆。
- 200 条固定 fixture 下的召回指标达到项目设定阈值；未命中查询不返回误导性“确定答案”。
- 删掉一个记忆文件后，诊断定位到文件；普通查询仍可在安全规则允许下继续运行。

### 9.2 CI 门禁

1. `npm test`、`tsc --noEmit`、构建均通过；
2. `core` 无 `@deepseek-ai/*` 导入；DSH 包不能直接导入文件写入实现；
3. 每条 `[机器门禁]` 都有策略映射和验证该行为的测试；
4. 配置 schema、文档和示例配置字段一致；
5. 锁定 Node/DSH 版本与 lockfile 无未审变更；
6. DSH 升级必须执行 S0 兼容性用例；
7. 固定召回测试输出 Recall@5、Precision@5、误召回率和延迟，低于门槛则阻止发布。

## 10. 运维与回退

- 每个阶段留 ADR：问题、选择、替代方案、证据、迁移/回滚办法。
- 备份包括 Markdown 源文件、提案决定账本、审计和必要的会话引用映射；索引缓存不要求备份。
- 发布包带版本号和 SHA-256 清单；升级前生成可恢复备份；升级脚本不得隐式清空或改写源文件。
- 初始化、schema 不兼容、审计恢复失败时明确阻断写入并给恢复步骤。单条记忆损坏可以隔离并继续只读读取其余数据，但不得把损坏内容当成有效结果。
- 每次 release 在真实 DSH 上通过新建 session、写一条、召回、采纳/拒绝提案、压缩、重启续接、重建索引的 smoke 流程。

## 11. 风险清单

| 风险 | 触发信号 | 应对 |
|---|---|---|
| DSH 版本变化 | 事件/注册/快照/压缩 API 不匹配 | 锁版本；先跑兼容性用例；改动限制在 adapter |
| 同进程权限过宽 | shell/子 agent 可直接读写记忆目录 | 不宣称 OS 隔离；收窄宿主沙箱或拆出独立服务身份 |
| 自动写入污染记忆 | 无来源、弱证据或矛盾条目增多 | 将推断内容放提案；限制活动写入为可追溯低风险类型 |
| 注入预算不足 | token 预算超限、规则被截 | 先压缩摘要/目录；不截断规则；记录各部分真实 token 量 |
| 检索误召回 | 错误条目进入前 5 或无答案时误返回 | 调整词法规则/元数据过滤；固定查询集不达标再评估 FTS/向量 |
| 审计与文件状态偏离 | 崩溃后缺事件或部分提交 | 操作 ID/恢复记录；doctor 检查；索引从源文件重建 |
| 蒸馏成本/负担过大 | 用户经常跳过提案 | 默认手动触发；减少候选上限；允许关闭，不后台提醒 |
| 原文隐私泄露 | 日志或提案保留多余会话文本 | 仅保存短引文/引用；日志不含 payload；提供按 ID purge 和备份策略 |

## 附录 A：调研结论与适用边界

| 方案/资料 | 可借鉴的设计 | 不直接照搬的部分 |
|---|---|---|
| `tigerless-labs/agent-memory`（MIT） | Markdown 为真相、索引可重建、按来源追溯、相似合并需人工审查、词法为基线且向量可选 | 它采用 Python/SQLite、sleep-time 管理和多宿主接入；其 README 自报的 benchmark 仅是项目自身协议，不能当成本项目效果保证 |
| MCP 官方 memory server | 本地 JSONL、写锁、原子保存、锁陈旧恢复、网络文件系统限制的明确说明 | 它是知识图谱示例，不是权限沙箱；并发锁策略需按本项目 Windows/NTFS 实测 |
| Letta memory blocks | 常驻记忆应有明确边界/容量；只读策略块是成熟模式；长期资料应区分常驻区和按需取回的 archive | Letta 的 agent 可直接编辑 memory blocks；本项目把规则与审批放在服务端，不能照搬其默认可写行为 |
| Mem0 | 产品级操作面明确包含 add/search/get/update/delete、元数据和 scope 过滤，提醒我们定义完整生命周期与 API 返回 | 其核心路径偏云服务/语义检索；本项目选择本地、可读源文件、人工审批和词法 baseline |
| Node.js 24 SQLite 文档 | `node:sqlite` 可用，但当前 24.x 文档标记为 Release Candidate | V1 暂不把它当稳定、零维护成本的默认基础 |
| DSH 官方仓库与 subsystem 文档 | 提示词、session、工具和 compaction 都有版本化扩展点；当前公开文档提到 system prompt 位于 session history，并描述压缩保护行为 | 当前 main 文档不能替代目标 `0.2.0-rc.2` 的实际验证；外部插件对实验 API 的可用性必须另证 |
| arXiv:2605.12978 | 一个受控 ARC-AGI 实验里，连续逐条整合在第 10 轮出现明显性能退化；支持保留原始证据并对整合设审批/回退 | 结果来自特定数据、模型和任务，不能泛化为所有 Agent 记忆“十轮后必然失效” |
