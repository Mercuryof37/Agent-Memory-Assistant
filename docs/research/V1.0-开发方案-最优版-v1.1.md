## 2. 保证分级与范围

### 2.1 三级表述

| 级别 | 含义 | 例子 |
|---|---|---|
| **机器保证** | 有代码检查，且有会失败的负向测试 | 模型工具表里没有 `decide`；零宽字符写入被拒绝；压缩不 shadow node 0（依赖 DSH 行为，需 M2 实测后标注） |
| **尽力而为** | 有检查但不能证明完备 | 密钥正则扫描；注入模式检测 |
| **不承诺** | 依赖模型或外部系统 | 模型遵守 `[模型指引]`；缓存命中；DSH 升级后行为不变 |

文档里出现"保证/禁止/必须"时，必须能在"机器保证"找到对应测试；找不到就改口径。

### 2.2 V1.0 做什么

| 模块 | 交付 |
|---|---|
| Core | schema、一记忆一文件（不可变）、有效期与替代链、词法检索、可重建索引、追加审计 + 哈希台账、事务恢复、权限策略 |
| DSH adapter | 工具注册（5 个）、`systemPrompt.section` 注入、可信来源绑定、`/closeout` 命令；只用 ADR-0003 确认过的接口 |
| CLI | 已有 `init`/`doctor`/`policy seal`；新增 `add`、`adopt`、`rebuild`、`recall`、`proposals`、`decide`、`inspect`、`export`、`purge`、`closeout` |
| 安全 | 输入校验、尽力而为的敏感内容检测、路径限制、失败关闭、审计最小化、**篡改可检测** |

### 2.3 不做 / 延后

| 项 | 处置 |
|---|---|
| 向量检索 / FTS5 / `node:sqlite` | 延后；固定查询集不达标才评估 |
| 自动后台整合 / 自动删除 / 自动 strategy | 不做 |
| Web 查看器 | 延后到 V1.1；V1 用 `mem inspect` |
| MCP 适配器、付费钩子、空包 | 延后到真有需求（ADR-0002）；`core-no-paid-hooks` 门禁保留 |
| 完整原始会话副本 | 不做；只存引用 + ≤160 字短引文 |
| 跨设备同步、多租户、`scope ≠ local` | 不做；`scope` 字段保留 |

## 3. 架构与选型

### 3.1 依赖方向

```text
packages/core   纯领域逻辑 + 全部文件 I/O；不依赖 DSH
packages/dsh    DSH 适配；只调 core 的 service；不碰文件系统
packages/cli    人专属入口；与 DSH 共用同一 service 和 policy
```

三条硬纪律已进 CI：core 不含宿主包字样；`dsh/src` 不 import `fs`；core 无商业化分支。快照落盘在 core（`core/src/snapshot/`），dsh 只调用。

### 3.2 目录结构

```text
packages/core/src/
├── config/ ✅  policy/ ✅  fs/ ✅  paths.ts ✅  init.ts ✅  startup.ts ✅
├── fs/lock.ts, fs/journal.ts        S2a 独占锁（租约 + PID）、事务日志
├── model/                           S2a schema、ID、frontmatter、有效期、类型
├── store/                           S2a CRUD、替代链、入账/隔离
├── audit/                           S2a audit.jsonl + ledger.jsonl（哈希链）
├── index/                           S2a manifest + 启动时内存索引；S3 BM25
├── inject/                          S3 纯函数渲染、预算、转义
├── snapshot/                        S3 会话快照读写与保留策略
├── scan/                            S4 Unicode / 凭据 / 注入模式
├── proposals/                       S4 待审账本、decide、decisions.jsonl
├── rules/                           S5 RULES.md 解析与映射校验
├── distill/                         S6 L0 打标、提案 schema
└── service.ts                       S2a→S6 MemoryService
packages/dsh/src/   settings.ts ✅ · plugin.ts · tools.ts · actor.ts · assemble.ts · closeout.ts
packages/dsh/cordis.patch.yml       插入本插件的行（bundle 形态）
packages/cli/       bin/mem.mjs ✅（命令逐阶段增加）
```

**插件形态**：`packages/dsh/package.json` 增加 `"dsh": { "bundle": { "patch": "./cordis.patch.yml" } }`。开发期在桌面 profile 里用 `link:<绝对路径>` 安装，重启后生效。安装只通过 app 插件页或 profile 文件，CLI 不能 boot 桌面 profile（ADR-0003 Q10）。

**回退触发**：S2a 结束时 `core` 源文件超过约 15 个，合并文件；包边界不动。

### 3.3 技术选择

| 领域 | 选择 | 约束 |
|---|---|---|
| 运行时 | Node **24.21.0**（`.node-version`）；`engines >= 24`；`npm run compat` 校验实际版本 | 与 DSH 宿主一致；开发机 25.2.1 只作日常 |
| 语言/构建 | TypeScript strict + `erasableSyntaxOnly`；esbuild | 不用 enum / namespace / 参数属性 |
| 测试 | `node:test`，默认单进程（沙箱不能 spawn 管道） | `AGENT_MEMORY_TEST_ISOLATED=1` 可回到默认隔离 |
| 权威存储 | 每条记忆一个 Markdown 文件，**创建后不可变** | 索引与缓存永不当真相 |
| 元数据 | frontmatter 每行 `key: <JSON 值>`，行切分 + `JSON.parse` | 不写 YAML 解析器、不引依赖；重复/未知/缺必填/多行值拒绝 |
| 检索 | 字段加权 BM25（启动时内存构建）+ 元数据过滤 | 不做 `Retriever` 多后端抽象 |
| 索引缓存 | 仅 `.index/manifest.json`（元数据 + 文件哈希）；倒排启动时现建 | 删掉必须能重建 |
| 审计 | `audit.jsonl` 追加 + 可轮转；**入账台账 `.state/ledger.jsonl` 独立、不轮转** | 台账是隔离判据，不能依赖可关的审计 |
| 并发 | 独占锁文件（`wx`）+ 租约（心跳 15s / 陈旧 5min **且 PID 不存活** / 获取超时 60s） | 只支持本地 NTFS；超时报错，不静默覆盖 |
| token 预算 | `ctx.tokenMeter.measure/estimateMessage`（S3 起） | 字符预算保留为兜底并标"估算" |
| 运行时依赖 | **零**（宿主包是 peer） | devDeps：`@types/node`、`esbuild`、`typescript`；S3 起加 DSH 包的精确版本 devDeps |

## 4. 数据模型

### 4.1 磁盘布局

```text
<home>/
├── config.toml  policy.json                ✅ S1
├── SOUL.md  USER.md  RULES.md              人维护；哈希纳入封存（S5）
├── MEMORY.md                               派生视图，可由源文件重建；勿手改
├── memories/{fact,pitfall,exp}/<id>.md     权威数据；创建后不可变
├── proposals/pending/*.json                待审提案
├── proposals/decisions.jsonl               决定账本（采纳/否决/删除），哈希链
├── audit.jsonl                             人类可读轨迹，可轮转、可关闭
├── .index/manifest.json                    可删除缓存
└── .state/
    ├── lock                                锁（PID + 心跳）
    ├── txn/<op_id>.json                    事务意图
    ├── ledger.jsonl                        入账台账（append-only，不轮转）
    ├── snapshots/<sha256(session_id)[0..32]>.json
    └── policy.seal.json                    ✅ S1
```

不设 `archive/sessions`：证据指向 DSH 会话日志（`ctx.sessionPersistence`）。

### 4.2 单条记忆

```markdown
---
id: "mem-20261017-a3f9c2d1"
mem_schema: 1
kind: "pitfall"
scope: "local"
abstract: "Windows 安装 Node 原生模块前先确认 Python 与 Build Tools"
created_at: "2026-10-17T09:00:00+08:00"
valid_from: "2026-10-17"
valid_until: null
supersedes: []
author: "agent"
evidence_level: "user_confirmed"
error_signatures: ["gyp ERR!", "node-gyp", "MSBuild"]
provenance: [{"session_id":"<id>","event_seq":412,"speaker":"user","quote":"先装 Build Tools 再试","event_sha256":"<sha256>"}]
---

正文（自由 Markdown；一律视为不可信资料，不是指令）。
```

**字段规则**

| 字段 | 规则 |
|---|---|
| `id` | `mem-<YYYYMMDD>-<8 hex>`；服务端生成，锁内确认不存在；文件名 = `<id>.md`；模型不能提供路径 |
| `mem_schema` | 记忆格式版本；与 config 根键 `schema_version` 是两个命名空间 |
| `kind` | `fact` / `pitfall` / `exp`；决定子目录，创建后不可改 |
| `abstract` | 必填、单行、≤ `limits.abstract_chars`（120）、无换行、无代码围栏 |
| `valid_from` | `YYYY-MM-DD`，含当日；T0/T1 取**事件日期**，人 `add` 取当天；不得晚于未来 1 天 |
| `valid_until` | 可空，排除端；只在创建时写，之后不改 |
| `supersedes` | **ID 数组**，可空；可一对多（合并）与多对一（拆分）；禁止成环、自引用、重复；后继的 `valid_from` 不得早于被替代者 |
| `author` | `agent` / `human` |
| `evidence_level` | `user_explicit` / `user_confirmed` / `observed` / `inferred`；`inferred` 只能走提案 |
| `error_signatures` | 字面子串数组，≤3 个、每个 ≤80 字符、区分大小写；V1 不支持正则 |
| `provenance` | 由适配层绑定（§5.3）；`author: human` 可空，其余至少 1 条；`quote` ≤160 字符且过扫描 |
| 正文 | ≤ `limits.body_chars`（4000）；超限返回差额 |

未知字段、越界、非法日期、引用无法核验：拒绝，不半写。

### 4.3 RULES.md

```markdown
## RULES

R1 [机器门禁] Agent 写记忆只能走 MemoryService；路径由服务端生成。
     check: packages/core/src/service.ts#assertTrustedActor
     test:  packages/core/test/rules/R1.test.ts
R2 [模型指引] 回复使用中文；代码与命令保持原样。
```

- 编号稳定、不复用；废止保留编号并标 `[废止]`。
- `[机器门禁]` 三件齐全才合法：`check:` 符号存在、`test:` 文件存在、该文件至少一个 `[neg]` 负向用例。CI 校验三项。
- `[模型指引]` 不得被描述成系统保证。
- agent 无写 `SOUL/USER/RULES` 的工具；三文件哈希并入封存（S5）。

### 4.4 MEMORY.md（目录，派生视图）

- 每行 `- [kind] abstract — id`；只列活动项；文件头注明"自动生成"。
- 分档只决定目录详细程度，**正文永不常驻**：≤30 全列；30–200 按优先级裁剪；>200 只列最高优先若干条 + 各 kind 计数 + 提示用 `memory_recall`。
- 优先级确定性：`evidence_level`（user_explicit > user_confirmed > observed > inferred）→ `valid_from` 新近 → `id`。V1 不引入 `weight` / 衰减。
- 裁剪只影响注入，不删记忆；被裁条目仍可召回。

### 4.5 有效期与替代

- 文件不可变；修订 = 新建条目并 `supersedes: [旧]`。
- 有效终点 = `min(valid_until, 所有后继的 valid_from)`；活动 = 查询日期落在 `[valid_from, 终点)`。
- `recall` 默认只返回今日活动项；`as_of` 返回指定日期活动项；历史链可 `read` 逐级追溯。
- `as_of` 使用本机时区；时区写入 ADR。

### 4.6 删除、合并、拆分（本版新增）

| 操作 | 表达 | 落地 |
|---|---|---|
| 删除 | T1 提案；采纳时写 `proposals/decisions.jsonl`：`{"op":"delete","target":id,"at":"…","base_hash":"…","actor":"human","reason":"…"}` | 源文件保留；`rebuild` 从 decisions 推导"已删除"；不进目录、不召回、不注入 |
| 合并 | 1 新条目 `supersedes: [旧1, 旧2, …]` | 旧条目自此失效；新条目来源必须覆盖全部旧条目的事件 |
| 拆分 | N 新条目各自 `supersedes: [旧]` | 旧条目自此失效；允许"一个旧条目有多个后继" |
| 物理删除 | `mem purge <id>`（人专属，S7） | 删文件 + manifest 项 + 目录项；decisions 留墓碑（只含 ID 与哈希） |

`decisions.jsonl` 是**第二真相源**：与 `memories/` 同级备份、带哈希链、纳入 `doctor` 校验。所有决定都要求 `base_hash` 与当前一致。

## 5. 服务、工具与权限

### 5.1 MemoryService

```ts
interface MemoryService {
  recall(q: RecallQuery): Promise<RecallResult>;      // { hits, warnings }
  read(id: MemoryId): Promise<MemoryDoc>;
  asOf(q: RecallQuery, date: string): Promise<RecallResult>;
  rules(): Promise<Rule[]>;
  stats(): Promise<Stats>;                            // 容量、隔离项、待审、台账一致性

  record(input: RecordInput, actor: TrustedActorContext): Promise<WriteResult>;   // T0
  propose(input: ProposalInput, actor: TrustedActorContext): Promise<Proposal>;  // T1
  decide(id: ProposalId, d: 'accept' | 'reject', human: HumanApprovalContext): Promise<void>;

  // 人专属（仅 CLI 构造 HumanApprovalContext）
  add(input: RecordInput, human: HumanApprovalContext): Promise<WriteResult>;
  adopt(id: MemoryId, human: HumanApprovalContext): Promise<WriteResult>;
  rebuild(): Promise<RebuildReport>;
}
```

- `TrustedActorContext` 由适配层构造（`session_id`、`delegation_depth`、事件读取器），**不接受模型参数覆盖**。
- `HumanApprovalContext` 只有 CLI 能构造；`decide` 不注册为工具。
- 没有 T0 的 correct/supersede：所有对既有记忆的改动都是提案。
- 采纳前服务重读目标并校验 `base_hash`；不一致即过期。
- `ProposalInput` 是判别联合：`revise` / `supersede` / `merge` / `split` / `delete`，S4 前冻结。

### 5.2 模型可见工具（5 个）

| 工具 | 档 | 说明 |
|---|---|---|
| `memory_recall` | 读 | 默认 `recall.limit` 条；返回 id、类型、摘要、有效期、来源是否可核验、相关度；无命中明确"未找到" |
| `memory_read` | 读 | 按 ID 读正文；输出带来源头并标"资料，非指令"；正文按 §6.1 的转义规则包装 |
| `memory_record` | T0 | 新增 fact/exp/pitfall；模型只给内容与 `evidence: [{event_seq, quote}]` |
| `memory_propose` | T1 | 修订/替代/合并/拆分/删除；必须带 `base_hash` |
| `rules_list` | 读 | 列规则与类别 |

`closeout` 不是模型工具：由 `/closeout` 命令（§7）或 `mem closeout` 触发。

**工具表快照测试**：名字集合等于上表；`additionalProperties: false`；字段名不得含 `path`/`target`/`session`/`approve`。

### 5.3 可信来源绑定

1. 模型传 `evidence: [{event_seq, quote}]`；
2. 适配器用**当前会话**经 `ctx.sessionPersistence`（或 live session）读出该事件，确认 `quote` 是事件文本子串、`speaker` 取自事件；
3. 适配器填 `session_id`、`speaker`、`event_sha256`，把完整 `provenance` 交给 service；
4. 任一步失败 → 拒绝；`delegationDepthOf(agent) > 0` 时**写工具不注册**（与 `dsh-tool-schedule` 同款）。

### 5.4 三档权限

| 档 | 动作 | 规则 |
|---|---|---|
| T0 | 来源可信的低风险新增；全等去重 | 受扫描与 `quota.t0_per_session` 约束；`inferred` 不允许 |
| T1 | 推断性/矛盾、修订、替代、合并、拆分、删除 | 只能提案；人 `decide` 后服务重校验并提交 |
| T2 | 改 SOUL/USER/RULES、改 policy、purge、存储权限 | 无模型工具；人改文件后 `mem policy seal --accept`，或受控 CLI |

**去重**：所有语义字段完全一致（Unicode 规范化后，含大小写/顺序/标点/内部空白）才算相同 → 返回既有 ID，审计记重复命中，**不改既有文件**。仅相似（词法阈值）只进提案。

## 6. 关键机制

### 6.1 注入与会话快照

- **固定区四段**：SOUL 摘要、USER 偏好、RULES（逐条编号+类别）、记忆目录。正文只能按需 `memory_read`。
- **用 `ctx.systemPrompt.section({ name:'agent-memory', order, text, interpolate:false })` 注册**；DSH 每轮会按当前 section 重渲染并替换 node 0，所以**文本必须由我们自己按 session 冻结**：core 生成快照，section 提供者读快照，同一会话字节不变。
- **压缩保护**：压缩范围从第一个非 system 节点开始，node 0 不会被 shadow（M2 实测后写进 README）。若实测不成立，退化为"每轮幂等重放快照"并声明限制。
- **预算**：优先 token（`ctx.tokenMeter.estimateMessage`，M3 标定）；不可用时退回字符并标"估算"。初始字符上限沿用 S1 键：SOUL 200 / USER 1500 / RULES 800 / 目录 1200，合计 3700。
- **RULES 超预算 → 启动/装配预检失败（退出码 2）**，不截断；目录超预算按 §4.4 确定性裁剪。
- **转义**：四段与召回结果统一用"随机 16 hex 分隔符 + JSON 字符串"包装；`memory_read` 渲染时转义反引号与围栏，防止结构逃逸。
- **快照文件**：`.state/snapshots/<sha256(session_id).slice(0,32)>.json`；键 = session_id + `memory_revision`（四段文本 SHA-256）+ `prompt_schema_version`。保留 30 天或最近 50 个会话，`mem inspect` 可见，`purge` 可清。
- 重启续接从快照恢复；缺失视为重新捕获并写 `snapshot_recaptured` 审计。
- **可见性**：目录冻结，但 `memory_recall` 实时可见；新写入不会进本会话目录，README/工具描述写明。
- 缓存命中只观测，不作正确性条件。

### 6.2 写入事务与恢复

1. 获取锁（读取之前，覆盖读—校验—写—审计全程）；
2. 读取并校验（含 `base_hash`）；
3. 写 `.state/txn/<op_id>.json`（目标路径 + 内容哈希）；
4. 原子写目标文件（临时文件 → rename；Windows `EPERM`/`EBUSY` 有限退避重试）；
5. 追加 ledger（`{id, sha256, op_id, at, prev}`，按 op_id 幂等）；
6. 追加 audit（可失败，不阻断；由 ledger 兜底）；
7. 重建 MEMORY.md/manifest；
8. 删 txn，释放锁。

**持久性**：原子 rename 不保证断电后内容落盘。V1 明确接受这一取舍并写进 README；如需更强，在 S7 评估 fsync 句柄（Windows 上可行，代价是每次写入变慢）。

**恢复**：启动发现 txn → 目标存在且哈希吻合则补 ledger/audit；目标不存在则回滚清除；其他情形阻断写入并点名。派生物不进事务，缺失或过期就重建。

**锁**：租约文件含 PID + 启动时间 + 心跳；陈旧判定 = 心跳超时 **且** PID 不存活（或 PID+启动时间不匹配），默认 5 分钟；获取超时 60 秒报错。

### 6.3 召回

- 分词：Unicode NFKC + 小写；CJK 二元组（单字一元）；ASCII 词；代码型片段（含 `- _ . : /` 或数字）整体保留并拆分。`tokenizer_version` 进 manifest，变化则全量重建。
- 打分：BM25（k1=1.2，b=0.75），字段权重 `error_signatures` ×4、`abstract` ×3、正文 ×1；`error_signatures` 字面命中独立加分。
- 未找到：低于 `recall.min_score` 或匹配词占比不足 → 返回空并明确"未找到"。
- 固定查询集：200 条记忆 + ≥40 查询，覆盖同义、中英混排、错误码、时间边界、失效、冲突、目录外、无答案。**fixture 在调参前先冻结**，避免过拟合。
- 门槛（首次基线后写 ADR，只升不降）：Recall@5 ≥ 0.80；无答案误返回 ≤ 10%；p95 < 50 ms；冷启动 < 1 s。CI 输出指标，低于门槛阻止发布。

### 6.4 写入前扫描（不可配置关闭）

范围：`abstract`、正文、`quote`、`error_signatures`、CLI 输入。

| 检查 | 动作 | 级别 |
|---|---|---|
| 不可见/双向 Unicode（U+200B–200F、202A–202E、2060–2064、2066–2069、非首位 FEFF、E0000–E007F） | 硬拒绝 | 机器保证 |
| 凭据特征（`sk-`、`AKIA`、私钥头、连接串） | 硬拒绝 | 尽力而为 |
| 提示词注入模式 | 拒绝，或降为待审提案（`scan.injection = flag`） | 尽力而为 |
| `<private>…</private>` | **不静默剥离**：T0 拒绝；T1 提案带脱敏文本，由人 `decide` | 机器保证 |

拒绝记录只含规则 ID 与字段名，不含命中原文；`adopt` 同样过扫描。

### 6.5 失败姿态与退出码

| 故障 | 姿态 | 退出码 |
|---|---|---|
| config / policy / 封存哈希 / RULES 映射异常 | 启动失败，点名文件与键/行号，给下一步 | 2 |
| schema 不兼容；txn/台账恢复失败 | 阻断写入，点名并给恢复步骤 | 2 |
| 单条记忆损坏，或未入账文件（手放/手改/直写） | 隔离该条：不进索引、不召回、不注入；其余正常；召回带 `warnings` | 4（`doctor`） |
| 派生物缺失/过期 | 自动重建并记审计 | 0 |
| 锁超时 | 报错，不覆盖 | 2 |
| 用法错误 | 打印用法 | 1 |

退出码 0/1/2/3 沿用 S1；**4 = 降级**（S2 起）。`doctor` 在隔离存在时返回 4；`smoke` 用新库，不受影响。

### 6.6 文件权限边界与篡改检测

**实测事实**：`workspace-write` 只 fence 写，不 fence 读（ADR-0003 Q5）。插件在宿主进程内运行，不受沙箱约束。

**V1 的表述**：

- 模型工具**没有写 `<home>` 的通道**（fs/bash 写被 fence；需 S2 写一条 FS 级拒绝测试）；
- 但**读不被 fence**：不宣称"agent 读不到"，只宣称"没有工具写入口 + 篡改可检测"。

**篡改可检测**：

1. `.state/ledger.jsonl`：每个文件的 `{id, sha256, op_id, at, prev}`；**哈希不在台账里的文件一律隔离**（不进索引/召回/注入），直到人 `mem adopt`。
2. `audit.jsonl` 可轮转、可关闭；轮转文件头写 `last_hash`，保持链连续。
3. `SOUL/USER/RULES` 的**规范化哈希**并入封存：去 BOM、LF、单个结尾换行；被改动 → 启动失败；人改完 `mem policy seal --accept` 并看到 diff。
4. `decisions.jsonl` 自带哈希链；被删改由 `doctor` 发现。

**已知局限（写进 README）**：同权限的恶意进程能同时改文件与台账；要对抗它需要独立 Windows 身份 + 窄 IPC，V1 不做。

**数据目录 ACL**：`mem init` 把 `<home>` 收紧到"当前用户 + SYSTEM"（Windows；失败则警告不阻断）。

## 7. 收尾蒸馏

- **L0（确定性）**：扫会话事件，标出候选证据（重复错误、用户纠正语、工具失败后成功、回滚），产出**事件引用列表**。
- **L1（人显式触发）**：用户输入 `/closeout`（`ctx.commands.register`）→ handler 调 `agent.followup({ content, source })` 启动一轮；提示词含 L0 清单与 JSON Schema 契约；模型用 `closeout_submit` 工具回应（**仅该轮临时注册**，工具表快照测试为这个例外留白）。失败或无法解析 → "本次未产出可解析提案"，不自动重试、不烧 token。
- 不使用独立模型客户端，不在会话结束时后台调用模型。
- 硬校验：每条候选含 `kind`/`abstract`/`evidence`/有效范围/预估副作用；证据必须回到 DSH 事件并通过 §5.3；模型自己的助手消息不算证据；与 RULES/活动记忆/待审/已否决去重；最多 5 条；无内容明确"本次无新提案"；只有 `decide` 采纳才写入，失败保留提案。
- 决定界面：`mem proposals` 一屏列候选（摘要、原文引用、代价为**模型估计**）；`mem decide --batch` 成批勾选。
- 可选 L2：工具失败输出命中活动 `pitfall` 的 `error_signatures` 时附一行提示。

## 11. 风险与回退

| 风险 | 触发信号 | 应对 |
|---|---|---|
| DSH 版本变化 / 接口非官方 | `compat` 失败；升级后 M1–M4 失败 | 锁版本；改动限制在 `packages/dsh`；先改方案 |
| 桌面 profile 只能由 app 管理 | 安装需重启；CI 无法装载 | 手工步骤写进 ADR；S0 尾款先做 |
| 同权限进程可同时改文件与台账 | 无信号（局限） | README 明写；不冒充安全边界 |
| 分层过度设计 | S2a 结束 core > 15 个文件 | 合并文件，保留包边界 |
| 注入预算不够 | RULES 超预算；目录裁得狠 | 精简摘要与目录；不截断规则 |
| 召回误召回 / fixture 过拟合 | 无答案误返回；真实误命中 | fixture 先冻结；补查询；不达标再评估 FTS5 |
| 审计与文件偏离 | `doctor` 报不一致 | txn 恢复；ledger 校验；派生物重建 |
| 蒸馏成为负担 | 连续两次跳过决定界面 | 上限降到 3；或只在主动想起时触发 |
| `RULES.md` 混入散文 | 无法映射的 `[机器门禁]` | CI 拦截；降级 `[模型指引]` |
| 估时偏差 | S0 降级分支 | 重估后再开 S3；未验证 API 不计入 |
| 原文隐私泄露 | 日志/提案出现多余原文 | 只存短引文与引用；拒绝记录不含原文 |
