## 2. 保证分级与范围

### 2.1 三级表述

| 级别       | 含义               | 例子                                  |
| -------- | ---------------- | ----------------------------------- |
| **机器保证** | 有代码检查 + 会失败的负向测试 | 工具表无 `decide`；零宽字符被拒；journal 断链阻断写入 |
| **尽力而为** | 有检查但不能证明完备       | 密钥正则扫描；注入模式检测                       |
| **不承诺**  | 依赖模型/外部系统        | 模型遵守 `[模型指引]`；缓存命中；DSH 升级后行为不变      |

README、RULES.md、工具描述里出现"保证 / 禁止 / 必须"时，必须能在"机器保证"一栏找到对应测试；找不到就改成"尽力而为"或"不承诺"。

### 2.2 做什么

Core 六件事（存储、有效期、检索、索引、审计、策略）+ DSH 适配（5 工具、注入、来源绑定、`/closeout`）+ CLI 全命令 + 安全（扫描、隔离、封存、篡改可检测）。其中"审计"由 journal 导出，不再有独立审计文件。

**Windows 持久化口径**：不承诺"rename 返回即代表断电后仍在"；只承诺"崩溃后状态可检测、可恢复、不静默丢数据"。写进 README。

### 2.3 不做

向量 / FTS5 / `node:sqlite`（固定查询集不达标才评估）；自动后台整合 / 自动删除 / 自动生成 strategy；Web 查看器（V1.1，用 `mem inspect` 文本版）；MCP 适配器、付费钩子；完整原始会话副本（只存引用与短引文）；跨设备同步、多租户；`scope ≠ local`。

## 4. 数据模型

### 4.1 磁盘布局

```text
<home>/
├── config.toml  policy.json
├── SOUL.md  USER.md  RULES.md
├── MEMORY.md                               派生视图（目录）
├── memories/{fact,pitfall,exp}/<id>.md     权威、不可变
├── proposals/pending/<proposal-id>.json    待审提案
├── .index/manifest.json                    缓存（含 journal_head）
└── .state/
    ├── lock  txn/  snapshots/  policy.seal.json
    └── journal/0001.jsonl                  唯一历史：入账、删除、决定、审计
```

不再有 `audit.jsonl`、`proposals/decisions.jsonl`、`.state/ledger.jsonl`。

### 4.2 单条记忆

frontmatter 每行 `key: <JSON>`；字段：`id`、`mem_schema`、`kind`、`scope`、`abstract`、`created_at`、`valid_from`、`valid_until`、`supersedes`、`author`、`evidence_level`、`error_signatures`、`provenance`。

- `id` = `mem-<YYYYMMDD>-<8 hex>`，服务端生成；文件名 = `<id>.md`；模型不能提供路径。
- `abstract` 必填、单行、≤120 字符；正文 ≤4000 字符（配置键）。
- `created_at`（ISO 带时区）与 `valid_from`（`YYYY-MM-DD`）分开；`valid_from` 含当日，`valid_until` 排除端。
- `supersedes` 是**数组**；禁止成环、自引用、重复；后继 `valid_from` 不得早于被替代者。
- `evidence_level`：`user_explicit` / `user_confirmed` / `observed` / `inferred`（只能走提案）。
- `error_signatures`：字面子串数组，≤3 个，每个 ≤80 字符，区分大小写；**不支持正则**。
- `provenance`：适配层绑定，`quote` ≤160 字符且过扫描；`author: human` 可空，其余至少 1 条。

未知字段、越界长度、非法日期、引用无法核验：拒绝，不半写。

### 4.3 RULES.md

- 编号稳定、不复用；废止条目保留编号并标 `[废止]`。
- `[机器门禁]` 三件齐全才合法：`check:`（符号存在）、`test:`（文件存在）、该测试文件里至少一个标题带 `[neg]` 的负向用例。CI 校验。
- `[模型指引]` 只影响模型，不得被描述成系统保证。
- agent 无写 `SOUL/USER/RULES` 的通道；三文件规范化哈希并入封存（S2b）。
- 解析器与 CI 映射校验在 **S3**（注入要逐条渲染编号与类别）。

### 4.4 MEMORY.md 目录

- 每行 `- [kind] abstract — id`，只列活动项；头部注明"自动生成"。
- 正文永不常驻；分档只决定目录详细程度：≤30 条全列；30–200 条按确定性优先级裁剪；>200 条只列高优先条目 + 各 kind 计数 + 提示 `memory_recall`。
- 优先级确定性：`evidence_level` 档位 → `valid_from` 新近度 → `id`。V1 不引入 `weight` 与衰减。
- 裁剪不删记忆；被裁条目仍可召回。

### 4.5 有效期与替代

- 文件不可变；修订 = 新条目 `supersedes: [旧]`。
- 有效终点 = `min(valid_until, 所有后继的 valid_from)`；活动 = `[valid_from, 终点)`。
- `recall` 默认今日活动；`as_of` 指定日期；历史链可 `read` 追溯。
- 例外：`mem adopt` 只更新 journal 里的入账哈希并留审计，不改文件。

### 4.6 删除 / 修订 / 合并 / 拆分

| 操作 | 表达 | 不变量 |
|---|---|---|
| 修订 | 1 新 `supersedes:[旧]` | `base_hash` 与当前一致 |
| 合并 | 1 新 `supersedes:[旧1,旧2,…]` | 每个 target 的 `base_hash` 各自核对 |
| 拆分 | N 新各自 `supersedes:[旧]` | 同一旧条目可有多个后继 |
| 删除 | journal `op:"delete"`，`{target, base_hash, reason}` | target 必须存在且活动；`op_id` 幂等；源文件保留 |
| 物理删除 | `mem purge <id> --accept`（S7） | 文件 + manifest + 目录项；journal 留墓碑 |

**重建顺序**：读 journal（权威历史）→ 读 `memories/`（数据真相）→ 按 journal 的 record/adopt/delete 得到"在账且未删除"集合 → 与文件对账。文件缺失但无 delete、或 delete 指向不存在/已删 → 隔离并入 `doctor` 报告。

### 4.7 journal：格式与不变量

```json
{"seq":1,"prev":"000…0","at":"2026-10-17T09:00:00+08:00","op":"record","op_id":"op-7f3a","data":{"id":"mem-20261017-a3f9c2d1","sha256":"…"}}
```

- `op`：`record`（新建入账）、`adopt`（承认手放/手改文件的哈希）、`delete`、`decide`（accepted/rejected）、`audit`（快照重捕获、隔离、重建等非权威事件）。
- 哈希：**该行字节（不含换行）的 SHA-256**；`prev` = 上一行的哈希，首行为 64 个 `0`。
- `seq` 从 1 连续递增；`op_id` 全局唯一，重复出现按幂等忽略。
- 分段：当前段超过 5 MiB 开下一段；段内首行的 `prev` 指向上一段末行。不删除旧段（`mem purge` 也不删）。
- manifest 记 `journal_head {seq, hash}`：末尾不一致 = 被截断，`doctor` 退出码 2，阻断写入。
- 重建时校验：链完整、seq 连续、每条 record 的 `sha256` 与文件一致。不一致的文件一律隔离。
- 人读轨迹：`mem inspect --audit` 从 journal 渲染，不再常驻文件。

## 5. 服务、工具与权限

### 5.1 MemoryService

```ts
interface MemoryService {
  recall(q: RecallQuery): Promise<RecallResult>;   // { hits, warnings }
  read(id: MemoryId): Promise<MemoryDoc>;
  asOf(q: RecallQuery, date: string): Promise<RecallResult>;
  rules(): Promise<Rule[]>;
  stats(): Promise<Stats>;
  record(input: RecordInput, actor: TrustedActorContext): Promise<WriteResult>;
  propose(input: ProposalInput, actor: TrustedActorContext): Promise<Proposal>;
  decide(id: ProposalId, d: 'accept' | 'reject', human: HumanApprovalContext): Promise<void>;
  add(input: RecordInput, human: HumanApprovalContext): Promise<WriteResult>;
  adopt(id: MemoryId, human: HumanApprovalContext): Promise<WriteResult>;
  rebuild(): Promise<RebuildReport>;
}
```

类型形状见附录 F，S2a 第一步落地为 `model/types.ts` 并用单测锁定。`decide`/`add`/`adopt`/`rebuild` 只由 CLI 构造的 `HumanApprovalContext` 调用；`decide` 不注册为工具。

### 5.2 模型工具（5 个）

`memory_recall`（默认 `recall.limit` 条）、`memory_read`（带来源头、按 §6.1 转义）、`memory_record`（T0，只给内容与 `evidence[{event_seq, quote}]`）、`memory_propose`（T1，必须带 `base_hash`）、`rules_list`。

工具表快照测试：集合相等；`additionalProperties:false`；字段名不含 `path`/`target`/`session`/`approve`。

### 5.3 可信来源

模型给 `{event_seq, quote}` → 适配器经 `ctx.sessionPersistence`（或 live session）读事件 → 校验 `quote` 是子串、`speaker` 取事件 → 填 `session_id`/`event_sha256`。失败即拒绝。`delegationDepthOf(agent) > 0` 时写工具不注册。

### 5.4 三档权限

T0（可信新增 + 全等去重，受扫描与 `quota.t0_per_session`）；T1（推断/修订/替代/合并/拆分/删除，只提案）；T2（改 SOUL/USER/RULES/policy、purge、存储权限，无模型工具）。

**去重**：语义字段完全一致（Unicode 规范化后）才返回既有 ID，journal 记重复命中；仅相似（词法阈值）只提示候选并进提案。

## 6. 关键机制

### 6.1 注入与会话快照

- 四段固定区（SOUL 摘要、USER 偏好、RULES、记忆目录），用 `ctx.systemPrompt.section({name:'agent-memory', order, text, interpolate:false})`；文本由 core 按 session 冻结。
- 预算：`ctx.tokenMeter.estimateMessage` 对合成 system 消息定价；不可用则 `chars ÷ 2.5` 并标"估算"；两值都记录。字符上限沿用 `inject.*`（合计 3700）。
- RULES 超预算 → 装配预检失败（退出码 2），不截断；目录超预算按 §4.4 确定性裁剪。
- 转义：四段与召回结果用随机 16 hex 分隔符 + JSON 包装；正文含 ``` / `</memory>` 不逃逸。
- 快照：`.state/snapshots/<sha256(session_id)[0..32]>.json`；键 = session + `memory_revision` + `prompt_schema_version`；**保留最近 20 个**，捕获时删最旧；`purge` 可清该会话。
- 重启续接从快照恢复；缺失重捕获并写 journal `audit` 行；目录冻结但 `recall` 实时可见（README 写明）。

### 6.2 写入事务与恢复

1. 取锁（读之前；覆盖读—校验—写—journal—派生物全程）；
2. 读 + 校验（含 `base_hash`）；
3. 写 `.state/txn/<op_id>.json`（目标路径、内容哈希、`op_id`）；
4. 写临时文件 → `fsync` → `rename`（Windows 上 `EPERM`/`EBUSY` 有限退避重试）；
5. 追加 journal `record` 行（含 `prev`）；
6. 重建 `MEMORY.md` + manifest（manifest 记 `journal_head`）；
7. 删 txn、释放锁。

**采纳提案**：先写全部替换文件到 `.state/txn/<op_id>/`，逐个 rename，再追加各自的 `record` 行（共享 `decision_op`），最后追加 `decide` 行。

**恢复**（启动）：txn 存在时按 txn 对账——文件已就位且 journal 已有对应 `op_id` → 只清 txn；文件已就位但 journal 缺 → 补行；文件未就位 → 清 txn 与暂存目录。链断、seq 断、文件哈希与 journal 不符 → 阻断写入并点名。`MEMORY.md`、manifest 是派生物，缺失或过期就重建。

**中断点**：通过向 service 构造函数注入 `beforeStep` 回调；生产构造默认无回调，它只能抛错，不是旁路。

### 6.3 召回

- S2a 先做**子串召回**（abstract + 正文，大小写不敏感），只验证 store → journal → index → recall 链路；S3 换 BM25。
- 分词：NFKC + 小写；CJK 二元组；ASCII 词；代码型片段（含 `- _ . : /` 或数字）整体保留并拆分；`tokenizer_version` 进 manifest。
- 打分：BM25（k1=1.2，b=0.75），`error_signatures` ×4、`abstract` ×3、正文 ×1；字面命中独立加分。
- 未找到：低于 `recall.min_score` 或匹配占比不足 → 空结果 + 明确"未找到"。
- 评估：fixture **60 条记忆、16 查询（12 dev / 4 held-out）**，覆盖同义、中英混排、错误码、时间边界、失效、冲突、无答案；指标 Recall@5、per-kind、误返回率、p95、冷启动、常驻内存。
- 门槛：**先测基线、写进本阶段的 ADR（0007），门槛取基线向下取整，之后只升不降**；不达标才评估 FTS5 / 向量（新 ADR）。

### 6.4 扫描（不可关闭）

范围：`abstract`、正文、`quote`、`error_signatures`、CLI 输入、`adopt`。

| 检查 | 动作 | 保证级别 |
|---|---|---|
| 不可见 / 双向 Unicode（U+200B–200F、202A–202E、2060–2064、2066–2069、非首位 FEFF、E0000–E007F） | 硬拒绝 | 机器保证 |
| 凭据特征（`sk-`、`AKIA`、私钥头、连接串） | 硬拒绝 | 尽力而为 |
| 提示词注入模式 | 拒绝，或降为待审提案 | 尽力而为 |
| `<private>…</private>` | 不静默剥离：T0 拒绝；T1 提案带脱敏文本 | 机器保证 |

拒绝记录只含规则 ID 与字段名，不含命中原文。

### 6.5 失败姿态与退出码

| 故障 | 姿态 | 退出码 |
|---|---|---|
| config / policy / 封存哈希（含 SOUL/USER/RULES）/ RULES 映射异常 | 启动失败，点名文件与键或行号，给下一步（`mem doctor` / `mem init` / `mem policy seal --accept`） | 2 |
| schema 版本不兼容；journal 链断/被截断；txn 无法对账 | 阻断一切写入，点名并给恢复步骤 | 2 |
| **单条**记忆损坏，或未入账文件 | 隔离该条：不进索引、召回、注入；其余正常 | 4（doctor）/ 召回响应带 `warnings` |
| 派生物（`.index`、`MEMORY.md`）缺失或过期 | 自动重建并写 journal `audit` 行 | 0 |
| 锁超时 | 报错，不覆盖 | 2 |
| ENOSPC / EACCES | 清理临时文件，点名路径，不写 journal | 2 |

**单条隔离并继续**不违反"没人问就继续"：范围限于一条、响应显式带告警、`doctor` 非零。禁止 `catch {}` 吞异常后报成功。

### 6.6 边界与篡改检测

- 实测：写被 fence、读不被 fence；插件进程不受限。只宣称"模型工具没有写入口 + 篡改可检测"。
- journal 不轮转；文件的哈希不在 journal → 隔离，直到 `mem adopt`。
- `SOUL/USER/RULES` 规范化哈希并入封存（`policy.sealed_files.soul|user|rules`，S2b 加，v2 内向后兼容）。
- manifest 的 `journal_head` 是 tripwire：被截断/断链 → `doctor` 报 2；manifest 可重建但 tripwire 只报警不自愈。
- 已知局限：同权限进程可同时改文件与 journal；更强需独立 Windows 身份 + 窄 IPC，V1 不做。
- `mem init` 把 `<home>` ACL 收紧到当前用户 + SYSTEM（失败警告不阻断）。

### S2a · 存储核心（4–5 天）

**产出**：配置冻结（新增 10 键、`recall.limit` 默认 5）；`model/types.ts`（附录 F）+ schema/ID/frontmatter/有效期；`fs/lock`；`journal/`（追加、链校验、恢复、`inspect --audit` 渲染）；`store`（CRUD、替代链、入账/隔离判定）；`index/manifest`（含 `journal_head`）；子串 recall；CLI `add`、`read`、`recall`、`rebuild`、`doctor` 扩展。

**验收**（5–6 条 journey）：

- `S2a.1` **薄纵切**：`mem add` → `mem read` → `mem recall` 命中 → `mem rebuild` 后仍命中；journal 有对应行；

## 附录 E：术语

| 术语 | 含义 |
|---|---|
| 记忆文件 | `memories/<kind>/<id>.md`，权威数据，创建后不可变 |
| 目录（MEMORY.md） | 派生视图，一行一条，可重建 |
| 索引（.index） | 缓存（manifest + 内存倒排），可删可重建 |
| journal | `.state/journal/NNNN.jsonl`，唯一历史：入账、删除、决定、审计；不轮转、不删段 |
| 提案 | 待人决定的候选，存 `proposals/pending/` |
| 决定 | journal 里的 `decide` 行（采纳/否决） |
| 隔离 | 未入账/损坏文件，不进索引、召回、注入 |
| 快照 | 会话冻结的注入文本，存 `.state/snapshots/` |

## 附录 F：类型冻结（S2a 落地）

```ts
export type Kind = 'fact' | 'pitfall' | 'exp';
export type EvidenceLevel = 'user_explicit' | 'user_confirmed' | 'observed' | 'inferred';
export type MemoryId = string;   // mem-YYYYMMDD-8hex

export interface ProvenanceEntry {
  readonly session_id: string;
  readonly event_seq: number;
  readonly speaker: 'user' | 'assistant' | 'tool' | 'system';
  readonly quote: string;          // <=160
  readonly event_sha256: string;
}

export interface MemoryDoc {
  readonly id: MemoryId;
  readonly mem_schema: 1;
  readonly kind: Kind;
  readonly scope: 'local';
  readonly abstract: string;
  readonly created_at: string;
  readonly valid_from: string;
  readonly valid_until: string | null;
  readonly supersedes: readonly MemoryId[];
  readonly author: 'agent' | 'human';
  readonly evidence_level: EvidenceLevel;
  readonly error_signatures: readonly string[];
  readonly provenance: readonly ProvenanceEntry[];
  readonly body: string;
  readonly file_path: string;
  readonly content_hash: string;
}

export interface RecordInput {
  readonly kind: Kind;
  readonly abstract: string;
  readonly body: string;
  readonly valid_from?: string;
  readonly error_signatures?: readonly string[];
  readonly evidence_level: Exclude<EvidenceLevel, 'inferred'>;
  readonly evidence?: readonly { readonly event_seq: number; readonly quote: string }[];
}

export type ProposalInput =
  | { readonly op: 'supersede'; readonly targets: readonly MemoryId[];
      readonly base_hashes: readonly string[];
      readonly replacements: readonly RecordInput[];
      readonly reason?: string }
  | { readonly op: 'delete'; readonly target: MemoryId;
      readonly base_hash: string; readonly reason: string };

export interface WriteResult {
  readonly id: MemoryId;
  readonly content_hash: string;
  readonly deduplicated: boolean;
  readonly warnings: readonly string[];
}

export interface RecallHit {
  readonly id: MemoryId;
  readonly kind: Kind;
  readonly abstract: string;
  readonly score: number;
  readonly valid_from: string;
  readonly valid_until: string | null;
  readonly provenance_verifiable: boolean;
}

export interface RecallResult {
  readonly hits: readonly RecallHit[];
  readonly warnings: readonly string[];
}

export interface Stats {
  readonly active: number;
  readonly total_files: number;
  readonly quarantined: number;
  readonly pending_proposals: number;
  readonly journal_head: { readonly seq: number; readonly hash: string } | null;
  readonly journal_consistent: boolean;
}

export interface JournalEntry {
  readonly seq: number;
  readonly prev: string;
  readonly at: string;
  readonly op: 'record' | 'adopt' | 'delete' | 'decide' | 'audit';
  readonly op_id: string;
  readonly data: Readonly<Record<string, unknown>>;
}
```
