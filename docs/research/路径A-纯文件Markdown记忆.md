# 路径 A：纯文件 Markdown 记忆（自研 DSH 插件，Amadeus 同构）

> **一句话**：把记忆存成几个你能用记事本打开、也能直接改的 Markdown 文件；写一个小插件在会话开始时把它们塞进系统提示词；所有写入只走一个专用工具，改前必读、服务端做版本校验、每次变更留本地 Git 历史。
>
> **适配环境**：DeepSeek Harness `0.2.0-rc.2`（本机实测）/ Node 24 / 单用户自托管
> **调研基准**：2026-10-17（star 数为当日 GitHub API 实测值）

---

## 一、这条路径用的是什么技术

这是最"土"也最稳的一条路。核心思想只有一句：**记忆就是文件，不是数据库。**

具体怎么跑起来，分四步：

1. **文件承载事实**。`SOUL.md` 存人格（散文），`USER.md` 存关于你的事实（条目），`MEMORY.md` 存跨任务的环境与约定（条目）。条目之间用单独一行 `§` 隔开，每个文件有字符上限。
2. **会话开场注入**。DSH 每次组装系统提示词时，插件把这三个文件的当前内容读出来，按固定排版塞进去。注入是在**会话开始时做一次**的"冻结快照"——这样同一会话里前缀缓存不会反复失效。
3. **写入只走一个工具**。agent 想改记忆，只能调 `memory` 工具（add / replace / remove / query）。工具内部强制"先读后写"：没读过就拒绝写入；服务端自己记版本号，模型根本看不到版本号，也就没法算错。
4. **落地可追溯**。每次保存前用租约锁防止并发写坏，写入走原子替换，并把历史提交进本地 Git——哪天记忆被改歪了，`git log` 能看到谁在什么时候改了什么。

这条路径就是你那篇语雀文章描述的架构，也是 Amadeus 的 `packages/personalization` 已经实现并跑通的架构。

### 技术栈一览

| 层 | 选型 | 作用 | 是否必须 |
|---|---|---|---|
| 宿主 | DSH `0.2.0-rc.2` + cordis 插件体系 | 提供扩展点，不改宿主代码 | ✅ 必须 |
| 运行时 | Node.js 24（ESM） | 插件运行环境 | ✅ 必须 |
| 注入点 | `systemPrompt.assemble` | 在提示词组装时注入记忆段 | ✅ 必须 |
| 快照记录 | `appendPluginRecord`（`plugin:amadeus-personalization/snapshot` v2） | 把本会话用到的快照写进日志，重启/恢复时可复现 | ✅ 必须 |
| 存储 | 纯 Markdown 文件 + `§` 分隔 + 字符预算 | 记忆本体 | ✅ 必须 |
| 读写通道 | 自研 `memory` 工具（唯一入口） | 校验、CAS、审计 | ✅ 必须 |
| 并发控制 | 租约锁（lease lock）+ 原子替换 | 防两个写者互相踩 | ✅ 必须 |
| 历史 | 本地 Git（每次写入提交） | 可回滚、可审计 | 推荐 |
| 行为约束 | `MEMORY_GUIDANCE` 分段注入 | 告诉 agent 什么时候存、什么时候问 | ✅ 必须 |
| 历史检索 | `session-query-global`（DSH 原生查询工具层副本） | 跨工作目录查会话 | 推荐 |
| 构建 | esbuild（`scripts/build.mjs`） | 打成 `dist/` | ✅ 必须 |
| 测试 | `node --test tests/*.test.mjs` + 真实浏览器脚本 | 单元 + 验收 | ✅ 必须 |

### 优势

- **零外部依赖**：不装向量库、不要 embedding、不要 API key、不跑第二个进程。一个 SQLite 都不需要。
- **人和 AI 共用同一份真相**：文件就是数据，出问题你直接打开看，不用写查询语句。
- **审计成本最低**：Git 历史天然给了"谁在何时改了什么"，配合日志快照还能复现"当时 agent 看到的是哪一版"。
- **控制力最强**：写入是否要你确认、子 agent 能不能写、容量满了怎么办，全在你自己手里。
- **升级风险最小**：只依赖 DSH 公开扩展点，宿主升级时通常只需改 peer 版本号。
- **有已验证的实现可对照**：Amadeus 已经在 `0.2.1-alpha.2` 上跑通，`dsh-memoir` 明确声明支持 `0.2.0-rc.2`。

### 劣势

- **容量是硬墙**：单文件 10000 字符，中文尤其吃紧（一个汉字约 1 token 量级），条目一多就得裁剪。被裁掉的条目**不可恢复**。
- **中文检索基本不可用**：字面匹配 + 默认分词器下，整句会变成一个 token。这是这条路最实在的短板。
- **快照语义反直觉**：本会话写的记忆，本会话看不见（要下个会话才进提示词）。不加文档说明，你自己都会以为"它怎么没记住"。
- **得自己写插件**：至少 TS 工程能力 + cordis 扩展点理解，不是装个包就完事。
- **只增不减**：有"替换链"但没有"过期检测"，长期跑下去会积累陈旧条目。

### 技术要求

| 项 | 要求 | 说明 |
|---|---|---|
| 编程能力 | TypeScript / Node ESM，能读懂 cordis 插件写法 | 中等。可照 Amadeus 结构搭骨架 |
| 对 DSH 的理解 | 知道 `systemPrompt.assemble`、`appendPluginRecord`、`ask_user_question`、preset 组装 | 必需，否则接不上注入点 |
| 机器资源 | 无特殊要求 | 纯文本，内存占用可忽略 |
| 外部账号 | **不需要** | 无 API key、无云服务 |
| 运维负担 | 低（一个进程，无额外服务） | 备份 = 复制目录 + `git log` |
| 上手时间 | 骨架 1–2 天，可用 1 周 | 有 Amadeus 可对照时更快 |

## 二、适用与不适用

**适合你，如果**：
- 你要的是"我的助手记得我是个什么样的人、记得我们的约定"，而不是"从十万条日志里检索"；
- 你重视可控、可审计、可手工修改，胜过语义召回率；
- 你愿意为"记忆质量"花人工确认的时间；
- 你运行在单用户环境（Amadeus 明确面向单用户自托管，不做多用户隔离）。

**不适合你，如果**：
- 你预期记忆条目会到几千条以上；
- 你需要"按语义模糊召回几周前的某段讨论"；
- 你不打算维护 TypeScript 工程。

## 三、架构与数据模型

> ⚠️ **位置决定强弱（关键）**：这个目录必须放在 **agent 文件沙箱之外**。DSH 的文件策略只允许工具改会话工作区；工作区外的路径 agent 的 `write`/`edit`/`bash` 够不到，而插件跑在宿主进程里不受此限。**文件放错位置，"唯一入口"就只是提示词里的一句话。** 详见 [06-约束硬化设计.md](06-约束硬化设计.md)。

```
<personalization.home>/        ← 必须在 agent 沙箱之外
├── SOUL.md           人格（散文，不由 memory 工具改）
├── MEMORY.md         跨任务事实（条目式，§ 分隔）
├── USER.md           用户事实（条目式，§ 分隔）
├── skills/<name>/SKILL.md
├── policy.json       容量/白名单/扫描规则（启动时哈希校验）
├── audit.db          追加写审计（含被拒绝的写入）
└── state/session-search.sqlite   可重建索引（真相仍是会话原始日志）
```

**运行链路**：

```
会话开始
  → systemPrompt.assemble 读取三份文件
  → 组装注入段（## MEMORY / ## USER，空文件不注入标题）
  → appendPluginRecord 写入 snapshot v2（本会话的"冻结事实"）
  → [对话进行] memory 工具：query / all / add / replace / remove
  → 成功压缩 → 只标记刷新；下一次 assemble 才重读
```

**关键语义**（照 Amadeus 的实现口径）：

| 规则 | 具体行为 |
|---|---|
| 分隔符 | 磁盘保持 `\n§\n`；注入时 `§` 前后加空行便于模型分条 |
| 容量 | 单次写入结果 ≤ 10000 Unicode 字符，**或**严格少于修改前；手工超限文件仍可完整读取 |
| 读前提 | 保存前必须读过该 target 的最新内容；服务端保存"本会话最近读到的内部版本" |
| 版本号 | 只在服务端内部流转，**模型不接收也不传递版本号** |
| 注入格式 | 有内容的文件用 `## MEMORY` / `## USER` 标题 + 空行；空文件不注入空标题 |
| 快照刷新 | 首次 assemble 捕获；普通步骤与失败重试沿用；成功压缩只标记，下一次 assemble 才重建 |
| 恢复 | 优先用最近有效插件记录；不可用时明确提示，**不拿当前磁盘冒充旧背景** |

## 四、关键实现点

**1. 别自己发明格式。** 直接用 `§` 单行分隔 + `## MEMORY` / `## USER` 标题，Amadeus 已经把排版打磨过：磁盘格式与注入格式分离（磁盘 `\n§\n`，注入加空行），空文件不注入标题。

**2. 版本号必须留在服务端。** 让模型传版本号是这条路最常见的错误——模型会算错。正确做法是服务端记住"这个 agent 最近读到的是哪一版"，写入时对比。

**3. 冻结快照不是可选优化。** 如果每次记忆编辑都重注入，每次写入都会击穿 prompt cache，成本静默上升且没有任何报错。

**4. 容量策略要选一个，并写进文档。** 四条已知路线：

| 策略 | 代表 | 行为 | 代价 |
|---|---|---|---|
| 硬拒绝 | 本项目现状 / Amadeus | 超限直接拒绝 | 可能重试；状态最干净 |
| 写入成功 + 提示重写 | Claude Code | 写入成功，但超限部分下次加载被丢弃，返回错误要求重写 | 磁盘与注入不一致 |
| 打 `over_limit` 标记 | opencode-agent-memory | 写入成功，标记超预算，让 agent 自己压缩 | 依赖 agent 自觉 |
| 磁盘不动、注入副本截断 | OpenClaw | 文件完整保留，只截断注入副本 | 静默不一致（最危险） |

**5. 降级要静默失败但不能整体崩。** Amadeus 的口径：文件缺失或编码异常时降级加载，**不能让对话整体失败**。反过来，初始化失败要**响亮报错**——Hermes 有个真实事故：`int()` 解析配置失败被 `except: pass` 吞掉，整个记忆子系统静默失效。

**6. 备份与回滚。** 目录级备份 + Git 历史。Amadeus 的部署约定值得抄：升级前备份、升级时不删卷、从已提交代码构建镜像并保留上一镜像标签。

## 七、开发流程（照 Amadeus 的做法）

Amadeus 的流程是这份文档里最值得抄的东西——它把"研究"和"实现"分开记账：

```
docs/research/
  2026-10-08-personal-agent-memory-survey.md      ← 先做 prior-art 调研（98KB）
  2026-10-09-amadeus-personalization-plan-draft.md ← 计划草稿（明确标注"待设计项不是接口"）
  2026-10-09-personalization-tools-files-design.md ← 工具与文件设计
  2026-10-10-personalization-implementation.md     ← 实现记录
  2026-10-11-dsbot-memory-comparison.md            ← 横向对比
  2026-10-11-memory-provenance-and-browser-capacity.md ← 来源与容量规则（最新为准）
```

配套约定（`AGENTS.md` 原文口径）：

> ⚠️ **先看清它的性质**：`AGENTS.md` 是一份 agent 会读的**文档**，只能影响"模型愿不愿意遵守"，无法决定"系统允不允许发生"。换模型、上下文被压缩、被注入文本覆盖，它都可能失效。**下面每一条要么有测试/守卫兜底，要么只能算软约束。** 硬化的完整方案见 [06-约束硬化设计.md](06-约束硬化设计.md)，其中给出了这 5 条各自的"可执行等价物"。

- **需求依据指向单一权威文档**；旧文档与新文档冲突以新版为准；`docs/research` 的历史记录**不随版本批量改写**。
- **不改写 `node_modules` 里的 DSH 代码**，定制一律走公开扩展点；确实没有扩展点时先说明取舍再决定。
- **每个行为改动都要有单元测试**（`node --test tests/*.test.mjs`）；涉及界面的跑真实浏览器脚本；无法自动化的（中文输入法、浏览器接管）**如实标注为需人工验收，不宣称已验证**。
- 发布用 `npm run pack:plugins` 输出归档 + `SHA256SUMS`。


## 八、里程碑与验收

| 阶段 | 产出 | 验收标准 |
|---|---|---|
| M1（1–2 天） | 三份文件的读写层 + `§` 解析 + 字符预算 | 单元测试覆盖：超限拒绝、条目内含 `§` 被拒、空文件不注入标题 |
| M2（2–3 天） | DSH 插件接线：assemble 注入 + 快照记录 | 新会话能看到注入段；`appendPluginRecord` 落日志；重启后恢复不串台 |
| M3（2 天） | `memory` 工具 + 读前校验 + 服务端版本 CAS | 并发写测试：第二个写者被拒且不改盘 |
| M4（1 天） | 租约锁 + 原子替换 + Git 提交 | 杀掉进程后文件不损坏；`git log` 可回溯 |
| M5（1 天） | 分段 guidance + 确认开关 | 子 agent 只读；主 agent 写入前提问 |
| M6（2 天） | 历史检索工具接入 | 跨工作目录能查到历史 |

**真实 Web 验收**（Amadeus 的做法，值得照搬）：先起隔离 profile，再把输出的 origin 设为测试环境变量跑 live 脚本，**只使用临时工作区和测试账号，不产生模型网络请求**。

## 九、风险、许可证与退出策略

| 风险 | 影响 | 应对 |
|---|---|---|
| **Amadeus 无 LICENSE** | 复制其代码有法律风险 | 只读文档与架构，自己实现；或改用 Apache-2.0 的 `dsh-memoir` 作参照 |
| DSH 版本破坏式更新 | 扩展点改名/改形状 | 只用公开扩展点；锁定 DSH 版本；升级前跑一遍验收 |
| 容量硬墙 | 关键边缘事实被挤掉 | 加 TTL/陈时清扫；把低频长内容挪到 skills 或历史检索 |
| 中文检索不可用 | 记忆"存进去但找不回" | 见路径 B；或先接受"靠注入不靠检索" |
| 快照语义被误解 | 你以为记住了其实没生效 | 把"新会话才生效"写进 troubleshooting |
| 单用户假设 | 多 workspace 会串 | 保持 `personalization.home` 固定，不跟随会话目录 |

**退出策略**：文件格式是纯文本，任何时刻都能迁到路径 B（导入 SQLite）或路径 C/D（导出为事实条目）。**这是路径 A 最大的隐藏优势——它不会把你锁死。**

---

## 十、结论

**如果只做一件事，做这条。**

理由不是它最强，而是它**最不容易后悔**：零外部依赖、人可读可改、可审计、可随时迁出。Amadeus 已经证明这套在 DSH 上跑得通，`dsh-memoir` 已明确支持你的 `0.2.0-rc.2`。

**但它必须配一个补丁**：把检索能力补上（路径 B 的 CJK 分词），或者明确接受"记忆靠注入、不靠检索"这个边界。否则你会遇到"它明明记过，就是想不起来"的挫败。

**下一步**：先按第七节建目录与 `AGENTS.md`，写 M1 的读写层 + 单元测试，不要一上来就接 DSH。

## 十一、外部调研补充（2026-10-17）

读外部材料后补的 5 条，都能直接落到本路径：

**1. `<private></private>` 内联隐私标记。** 写入前扫描，命中则整段丢弃并记审计 `skipped: private-tag`，**不报错、不提示模型**（否则它会换个说法再写一遍）。价值在于这是用户侧的确定性开关，不依赖模型是否听话。

**2. 只读记忆检查器。** 我们已有 Git 历史与审计表——那都是给机器看的。人真正会问的是"**它现在到底认为我是个什么样的人**"，这需要一屏看完。建议阶段一就做三个只读接口（记忆渲染 + 预算进度 / Git 历史 / 审批对），**先只读，别做编辑**。

**3. `PLAN.md` 独立成层，不进记忆预算。** 内容归属修正：

| 内容 | 归属 |
|---|---|
| 人格、偏好、长期约定 | `SOUL/USER/MEMORY.md` |
| **当前任务计划与进度** | **工作区内 `PLAN.md`**（有完成判据，任务结束随项目归档） |
| 跨会话交接 | `AGENT_HANDOFF.md` |
| 可复用流程 | `skills/` |

把计划塞进 `MEMORY.md` 是这类系统最常见的容量杀手。

**4. 写入前安全扫描（服务端）。** 记忆是注入系统提示词的，等于把外部可控文本放进最高优先级位置。四项硬检查：**不可见 Unicode**（零宽/双向控制符）、提示词注入模式、凭据特征（`sk-`/`AKIA`/私钥头/连接串）、外泄指令。**必须在服务端，和审批门同一位置**——放工具层就能被绕过。

**5. 值守子代理只产出候选、不落盘。** 一个只读子代理监听会话与其它子代理，产出 `{content, type, scope, source, confidence}` 进 pending 队列，由主 agent 或人复核。这把"捕获"与"整合"拆开，符合"整合要过门槛"的结论。

**6. `MEMORY.md` 内区分 `[fact]` 与 `[exp]`。** 世界事实（"用户项目用 Axum"）与自身经历（"我上次装依赖失败，因为 Node 版本"）的**衰减规律不同**：前者因外部变化失效，后者因环境变化失效但教训可留。

完整规范见 [08-结构细节补齐与CSDN文章取舍.md](08-结构细节补齐与CSDN文章取舍.md)，要点四条：

- **磁盘加前缀**（`[fact]` / `[exp]`，写入必填，`[exp]` 必须带 `YYYY-MM-DD`），**注入改为分组**（`### 世界事实` / `### 自身经历`）——前缀占字符，注入不该重复付这个成本；
- **`[exp]` 子预算 ≤ 40%**（4000 字符）：经历会自然堆积，不限流会把"用户是谁"挤出去；
- **衰减**：`[fact]` 90 天未复审标「待核实」，`[exp]` 60 天转「待复盘」（升 strategy 或归档）；**没有自动删除**；
- **`strategy/` 目录**补上缺失的中间层，且**不进常驻注入**，按需检索。

**7. 把上下文划出"不可变区"。** 这是 `billion-context-dsh` 用血换来的教训（压缩掉 `AGENTS.md` 当前副本 → 宿主重注入 → 死循环）：

```
不可变区（压缩/滑动/重写一律不得触及）
├── 系统提示词固定开场
├── MEMORY / USER 注入段
├── MEMORY_GUIDANCE 当前副本
└── 工具定义
可变区（可压缩、可摘要、可滑动）
└── 对话轮次、工具结果、中间结论
```

落地要求：注入段的 seq 范围标 `protected`；压缩请求若覆盖它 → **硬拒绝并点名可重切的区间**；测试断言"压缩 20 次后注入段字节不变"。**不是"压缩时小心别碰"，而是"它根本不在可压范围里"。**

**8. 权限分三档，不要二元。** 之前只写了"确认 / 不确认"，那是两个极端。更成熟的模型（来自 `agent-memory` 的 authority tiers）：

| 档 | 谁执行 | 适用动作 | 为什么 |
|---|---|---|---|
| **T0 自动** | 无人值守即可 | 新增、更新（保留旧版）、**全等**去重合并 | 都可回滚 |
| **T1 提案** | 系统提议、人确认 | **删除**、**相似度**合并、拆分、跨作用域移动 | 不可逆或易错 |
| **T2 仅人工** | agent 无入口 | 物理清理、策略变更 | 不可逆且危险 |

判据一句话：**新增与更新可以自动，删除只能提案**——因为前者可回滚，后者不可逆。它的原话是"unattended pass may add and update, deletion only ever arrives as a proposal you confirm"，并且"cannot delete anything unattended"。

**9. 注入分档：别把正文全塞进去。** `agent-memory` 的做法是 `MEMORY.md` **只做索引**（一行一条，"the only resident injection"），正文按需读。这直接绕开我们的 10000 字符硬墙。建议分档：

| 记忆规模 | 做法 |
|---|---|
| ≤ 30 条 | 直接注入正文（现状，零额外跳数） |
| 30–200 条 | **混合**：`[fact]` 短条目注入正文，`[exp]` 与长正文只给索引行 |
| > 200 条 | 全索引 + 按需读 |

**混合档最适合本项目**：事实短、经历长，正好一个注入、一个索引。

**10. 先落原始轨迹，再做蒸馏。** 顺序不能反。`agent-memory` 的口径是"the full trace is copied first, so 'missed by the distiller' never means 'lost by the system'"——**捕获由系统保证，不由模型裁量**。对应本文第 5 条（值守子代理），但更强：光有候选不够，原始轨迹必须先落盘。
