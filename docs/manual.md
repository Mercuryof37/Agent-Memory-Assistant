# 记忆助手使用手册

> 这是一份写给使用者的说明。它讲的是「能做什么、怎么用」，不解释内部原理。

## 这个助手能帮你记住什么

它给你的 AI 助手装了一套**长期记忆**：你们确认过的事实、踩过的坑、经验，会存下来，下次开新对话时助手仍然知道。记忆是**逐条**的，每条有自己的标题（摘要）和正文；修订不会覆盖旧条目，而是产生一个新版本，旧的仍可查。

记忆分三类：

- **事实**：稳定成立的知识、约定、结论；
- **坑**：容易犯的错误，带触发它的特征（报错关键字、场景）；
- **经验**：一套做法、流程、技巧。

## 你的助手是谁、怎么说话

第一次使用时，让助手建好「人设文件」（或者自己运行 `/mem scaffold`）：

```text
/mem scaffold
```

它会生成三份文件，你按注释填内容就行：

- **SOUL.md**：助手的人格、身份、语气边界（只取前 200 字注入）；
- **USER.md**：关于你的长期偏好，一条一段，用单独一行 `§` 分隔；
- **RULES.md**：约定；[硬] 规则要能被检查才算数。

改完运行 `/mem seal --accept` 生效。想看看助手现在知道你的什么偏好：`/mem profile`；按关键词找：`/mem profile 称呼`。助手也可以帮你改 USER.md，但每次都会弹卡片让你确认。

## 图形界面：侧栏「记忆」

重启应用后，左侧栏会多一个「记」图标（悬停显示「记忆」）。点开就是工作台：

- **列表**：按 事实 / 坑 / 经验 分组，每组内按时间从晚到早，前面的编号 `F-01`、`P-01`、`E-01` 方便口头指代；
- **详情**：点任意一条，展开正文与出处（哪句话、哪条消息）；
- **搜索**：顶部输入关键词；
- **导出备份**：下载一个 JSON 文件；
- **提案**：右上角「提案 N」看助手想改什么；「采纳」才生效，「驳回」就丢弃；
- **修订 / 删除**：打开一条记忆后，可以改摘要与正文，或删除；删除前会再问一次；
- **偏好与规则**：右上角「偏好与规则」里编辑你的偏好（USER.md）和规则（RULES.md）；规则保存后立即封存，下一轮对话生效；
- **命令手册**：右上角小按钮，里面是全部 `/mem` 命令——日常不需要它。

## 助手能翻旧对话

遇到「上次我们是不是说过……」这类问题，助手可以去翻历史会话（只读）：跨会话搜索、看某一场对话里的原文、追一条消息后来被谁替换过。你不用做任何配置，直接问就行。

## 助手能写多深：三种权限

在 `config.toml` 里有一行 `[personalization] mode`，决定助手能不能自己改记忆与偏好：

| 模式 | 行为 |
|---|---|
| `confirm`（默认） | 每次写记忆/偏好前弹卡片，你同意才写 |
| `direct` | 助手自主判断并直接写，只保留出处审计 |
| `readonly` | 只读：只能查，不能写；需要改动时把建议交给你 |

改完重启生效。无论哪种模式，**删除与彻底清除都只能由你执行**。

如果想按会话切换，而不是全局改配置：用 `npm run preset -- --id memory-ro --mode readonly --out memory-ro.patch.yml` 生成一份 preset 补丁，按 [presets 说明](presets/README.md) 追加到 profile，重启后在「设置 → 通用 → Agent preset」里选择；只读 preset 里助手连写工具都看不到。

## 日常怎么用

### 1. 让助手记住一件事

直接说就行，比如：

> 记住：部署前必须先跑数据库迁移，否则启动会报错。

助手会去看你**原话**作为出处，然后写下这条记忆。它不是凭空记——每条记忆都能追溯到你当时说的那句话。

### 2. 让助手改一条记忆

说「把那条改一下」「这个说法过时了」，助手会先给你一张**审批卡片**：

- 卡片上写着：改哪条、为什么改、改后的完整内容、出处；
- 三个按钮：**采纳** / **驳回** / **暂不处理**。

你点「采纳」，改动才生效；点「暂不处理」，提案留着，以后想起来了再处理；点「驳回」，原记录不动。

> 助手不能自己批准自己的改动。所有修订都要你亲手点。

### 3. 想看看记住了什么

- 问助手「你记得关于部署的什么？」——它会去搜；
- 或者直接在聊天框输入：`/mem recall 部署`；
- 想看全貌：`/mem inspect`（有多少条、哪些待审、最近发生了什么）。

### 4. 手动加一条

在聊天框输入：

```text
/mem add --kind fact --abstract "一句话摘要" --body "详细内容"
```

`--kind` 可以是 `fact` / `pitfall` / `exp`（默认 `fact`）。

### 5. 删掉一条

- 普通删除（记录失效，但历史仍可查）：`/mem delete <记忆编号> --reason "原因"`；
- 彻底清除（文件也删掉）：`/mem purge <记忆编号> --reason "原因" --accept`。

### 6. 备份与迁移

```text
/mem export D:\备份目录
```

会把记忆、待审提案、历史记录和配置一起导出，并生成校验清单，方便换电脑或定期备份。

### 7. 处理待审提案

```text
/mem proposals                查看待审提案（含摘要和怎么决定）
/mem decide <提案编号> accept  采纳
/mem decide <提案编号> reject  驳回
/mem decide --batch accept     一次处理全部待审
```

### 8. 其他常用

| 输入 | 作用 |
|---|---|
| `/mem read <记忆编号>` | 看某条记忆的全文与出处 |
| `/mem profile [关键词]` | 看 USER.md 里的偏好条目 |
| `/mem scaffold` | 生成 / 补齐 SOUL、USER、RULES 模板 |
| `/mem adopt <记忆编号>` | 承认你手改过的记忆文件 |
| `/mem rebuild` | 重建索引（数据修复后用） |
| `/mem seal --accept` | 重新封存「人专属文件」的指纹（USER 默认不封） |
| `/mem help` | 列出全部命令 |

## 三个需要知道的规矩

1. **修订必须人批**：助手只能「提议」，不能自己生效；删除和清除也需要你确认。
2. **每条记忆有出处**：助手写记忆时必须引用你说过的话；来自文本修改的记忆也会保留原始出处。
3. **记忆不可篡改**：改一条会生成新版本，旧版本保留可查；彻底清除会留下「已清除」的记录，避免数据看起来像丢了。

## 建议的使用习惯

- 说「记住」之前，把话说完整、说具体——记忆的可读性取决于你原话的质量；
- 定期看一眼 `/mem proposals`，别让待审提案积压；
- 重要项目开始前 `/mem export` 留一份备份；
- 不要往记忆里放密码、密钥、私人证件号——系统会拒绝明显像密钥的内容，但别依赖它。

## 常见问题

**卡片没出现？**
说明当前界面没有可用的审批入口。提案会保留，之后可以再弹出来，或者在聊天框用 `/mem proposals` 查看、用 `/mem decide` 决定。

**为什么不能直接让我点「采纳」就完事？**
因为这是「你的记忆」。助手可以起草、可以提醒，但最后的决定权在你手里。

**记忆存在哪里？**
存在本机，只有你（和你的助手）能访问。换机器时用 `/mem export` 带走。

**删错了怎么办？**
普通删除只是让记录失效，历史还在，可以用 `/mem read <编号>` 找回原文；彻底清除（purge）无法恢复，操作前请确认 `--accept`。
