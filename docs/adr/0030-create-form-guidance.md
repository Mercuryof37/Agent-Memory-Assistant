# ADR-0030 · 新增入口收敛与填写指导

- 状态：已实现（待真实桌面复验）
- 日期：2026-10-18
- 阶段：V3.1 收尾
- 依据：[ADR-0028](0028-v31-manual-workflows.md)

## 问题

1. 工具条有「＋ 新增」，每个分组标题也有「＋」，两个入口重复；用户要求只保留分组里的「＋」。
2. 新增表单只有 placeholder，没有说明每个字段到底填什么，尤其「坑」的摘要/正文/错误特征三栏语义不清。

## 选择

1. **删除工具条「＋ 新增」**，保留三个分组标题右侧的「＋」（按分组预选类型）。
2. **表单改为"标签 + 说明 + 控件"**：
   - 摘要：一句话说清是什么；列表/提案显示的就是它；给示例（坑的示例用真实报错场景）。
   - 正文：触发条件、现象、最后怎么处理；可直接粘贴报错。
   - 日期：从哪天开始适用；留空用今天。
   - 错误特征（仅坑）：1–3 条，逗号分隔，**按字面匹配、不写正则**；给示例 `ECONNREFUSED 5432`、`Win32 error 5`。
3. **坑的填写说明**：选择「坑」时出现浅蓝提示条——摘要写"踩了什么坑"，正文写"怎么触发、怎么解决"，错误特征写"报错里固定不变的片段"。

## 被否方案

- **保留双入口**：两个「新增」行为一样，容易让用户以为有区别。
- **只加 placeholder**：长 placeholder 会被输入内容遮住，且无法说明"为什么填这个"。
- **把错误特征做成多行列表编辑器**：V3.1 先用逗号分隔；V3.3 再评估结构化输入。

## 证据

- `ci` 全绿：**254 个测试**。`S13.1` 增加断言：源码不含「＋ 新增」、含「错误特征（1–3 条，必填）」「按字面匹配，不写正则」「坑怎么填」。
- 客户端构建成功；三个分组「＋」保留，表单为标签式说明。

## 偏差与回滚

- 提示条只在选择「坑」时出现；事实/经验仍显示通用字段说明。
- 回滚：恢复工具条「＋ 新增」与旧 placeholder。
