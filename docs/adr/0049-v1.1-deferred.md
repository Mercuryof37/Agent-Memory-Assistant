# ADR-0049 · V1.1 顺延项收口：home 的 junction 与锁的 PID 复用

- 状态：已实现（T9 / Q8）；接受（T10 / Q4）
- 日期：2026-10-18
- 依据：[todo.md](../plan/todo.md) T9/T10、[open-questions.md](../plan/open-questions.md) Q4/Q8、[ADR-0005](0005-s2a-store.md)（锁）、[ops.md](../ops.md) §4/§9

## 问题

- **T9 / Q8**：`--home`、`AGENT_MEMORY_HOME`、`DSH_HOME/memory` 指向 junction 或符号链接时，写入、备份、导出都悄悄跟随；旧代码只校验路径形状与 id 形状，策略未定。
- **T10 / Q4**：锁只在"心跳过期 **且** PID 不存活"时被接管；PID 被无关进程复用时，过期锁会被误判为"进程还活着"，一直超时。

## 选择

### home 经过链接：默认拒绝，显式放行（实现）

1. `canonicalizeHome(home, { allowJunction })`（`packages/core/src/paths.ts`）：检查**存储目录本身**与**直接父目录**是否指向别处。判定用 `realpathSync.native(p)` 与 `realpath(父目录) + 名字` 比较——Windows 上 libuv 把 junction 报成普通目录，`lstat().isSymbolicLink()` 为 false、`readlink` 报 `EINVAL`，不能作为判据。
2. 默认抛 `HOME_INVALID`，点名那个链接，提示 `--allow-junction` / `AGENT_MEMORY_ALLOW_JUNCTION=1`。
3. 显式放行后返回真实路径；`startup`、`initStore`、`scaffoldPersonalization`、`sealPolicy` 统一走它。DSH 侧 `openHostService` 用 `runtime.home` 建 store，`plugin.ts` 后续路径也换成 canonical。
4. 只检查两级：更高层的重定向（如企业策略重定向的 `C:\Users`）视为机器布局，静默跟随——避免把普通用户的默认路径判成违规。
5. 正常目录不触发任何 realpath 规范化：`runtime.home === 输入`，既有行为与测试不变。

### 锁的 PID 复用：接受（不修）

1. Node 没有跨进程读取启动时间的 API。
2. Windows 上只能靠 PowerShell / WMI，需要**管道**读取输出；宿主沙箱禁止子进程管道（ops.md §3 已记录 EPERM），而且每次探测都要 spawn。
3. 引入原生扩展可以拿到进程句柄，但代价是打破"运行时零依赖"，与 ADR-0002 的取舍冲突。
4. 现状的风险是**可用性**（超时失败、点名锁文件），不是数据损坏：绝不覆盖活进程。
5. 恢复步骤写进 ops.md §9：确认没有 `mem` 进程后删除 `<home>/.state/lock`。
