# ADR-0024 · GUI 删除改为彻底删除（含被替代版本）

- 状态：已实现（待真实桌面复验）
- 日期：2026-10-18
- 阶段：V2 P3.8（删除语义修正）
- 依据：[ADR-0022](0022-backup-import.md)、[ADR-0023](0023-dedupe-sort-toolbar.md)

## 问题

用户在 GUI 里删除一条记忆，再从备份导入，发现被删的那条没有回来。

原因有两层：

1. 旧删除走「delete 提案 + 接受」→ `store.remove`：文件不删，只记 journal；`findDuplicate` 会跳过已删除 id，所以**内容相同的导入仍会按内容去重跳过**；
2. 更关键：如果删的是修订后的新版本，`store.remove` 只删新版本，**旧的被替代版本会重新变成活动记录**；从用户视角像「删了又复活」。

## 选择

1. **GUI 删除 = 彻底删除**：`deleteGui` 改为 `store.purge`（物理移除记忆文件，失效相关 pending 提案）。
2. **连同被替代版本**：删除一条修订后的记录时，递归收集它的 `supersedes` 祖先并一并 purge；否则清掉新版本会让旧版本复活。
3. **journal 语义**：journal 是追加式审计链，**不能删行**（删行会断链、导致启动完整性失败）。purge 只写一条 `delete{purged:true, reason, sha256}`，**不保留正文**；记忆文件已删除，正文不可恢复。
4. **导入恢复**：文件被物理删除后，备份里的同内容记录可以重新导入（如唯一）；若同内容仍有活动副本，则按上一轮的内容去重规则跳过——这是去重语义，不是删除残留。

## 被否方案

- **从 journal 物理删除行**：破坏哈希链与 `journal_head`，启动会判定 journal 不一致；且审计不可追溯。
- **删除时清空 supersedes 关系**：会改变历史记录语义，且旧版本文件仍在。
- **只删新版本、保留旧版本**：正是这次「删了又回来」的根因。

## 证据

- `ci` 全绿：**248 个测试**。新增 `S14.13`：唯一记录删除后，备份可重新导入（imported 1）；`S14.6` 更新后验证修订链删除后不会复活旧版本。
- 客户端确认文案改为「彻底删除…journal 只留下删除记录（不含正文）」。

## 偏差与回滚

- 已存在的「重复内容」仍按内容去重，不会因删除其中一条而让备份恢复另一条；需要先删掉所有同内容副本再导入。
- 删除祖先版本会连带删除历史修订文件；journal 仍保留 id 与原因（无正文）。
- 回滚：`deleteGui` 恢复为 delete 提案 + `store.remove`；恢复原确认文案。
