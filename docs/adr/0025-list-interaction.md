# ADR-0025 · 分组折叠、详情置顶与切换收起

- 状态：已实现（待真实桌面复验）
- 日期：2026-10-18
- 阶段：V2 P4（列表交互）
- 依据：[ADR-0023](0023-dedupe-sort-toolbar.md)、[UI 命名规范](../design/ui-guidelines.md)

## 问题

1. 三个分组一次性渲染全部条目，记忆多了以后页面很长；
2. 详情卡渲染在列表末尾，点开一条要滚到底才能看；
3. 打开详情后切到「提案 / 偏好与规则」，详情仍留在页面上方或下方，状态互相干扰。

## 选择

1. **每组最多 8 条**：先渲染 `items.slice(0, 8)`；超过 8 条的部分放进下方独立的滚动区（`max-height: 320px`，`overflow-y: auto`），复用细滚动条样式，并标注「还有 N 条，向下滚动查看」。
2. **详情置顶**：工作台容器改为纵向 flex；详情卡 `order: 1`，列表区 `order: 2`，因此详情总在工具条/提示之后、列表之前出现；打开条目时把滚动容器滚回顶部。
3. **切换即收起**：打开「提案」「偏好与规则」、执行搜索、切换条目时，统一清空 `detail` / `revise`；提案面板同时收起「查看详情」的展开态。
4. **搜索也收起详情**：避免搜索结果与旧详情同屏。

## 被否方案

- **每组虚拟滚动**：当前量级（几十到几百条）不值得引入虚拟列表；嵌套滚动 + 8 条上限已够。
- **详情用弹窗**：会遮住列表与上下文；置顶内嵌卡更符合「边看边改」。
- **详情固定在右上角**：与主面板布局冲突，窄窗口不可用。

## 证据

- `ci` 全绿：**248 个测试**；`S13.1` 新增断言：`slice(0, 8)`、`还有 ${...}`、`maxHeight: "320px"`、`order: 1/2`、切换时 `setExpandedProposal(null)`。
- 构建产物重新生成；手工验收点：事实 8 条以内正常显示，超过 8 条出现滚动区；点任意条详情出现在顶部；打开提案页详情消失。

## 偏差与回滚

- 8 条上限是常量（写死在客户端），暂不做配置；V3 可放进设置。
- 详情置顶依赖 flex order，宿主若替换主面板容器样式需复验。
- 回滚：恢复一次性渲染、详情放列表末尾、切换面板不清空状态。
