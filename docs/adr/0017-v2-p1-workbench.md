# ADR-0017 · V2 P1：只读工作台

- 状态：已实现（待真实桌面复验）
- 日期：2026-10-18
- 阶段：V2.0 P1
- 依据：[V2.0 方案](../plan/v2-gui-and-distribution.md) §4、[ADR-0016](0016-p05-section-registry.md)

## 问题

P0 只验证了「能显示一页状态」。P1 要让不碰命令行的用户能：按类型浏览记忆、看详情与出处、搜索、导出备份；命令行手册退到一个小按钮里。

## 选择

1. **数据面**（`packages/dsh/src/gui.ts`）：五个只读路由，全部经 `MemoryStore`，不碰文件：
   - `GET /api/agent-memory/status`（沿用 P0）
   - `GET /api/agent-memory/list`
   - `GET /api/agent-memory/item?id=`
   - `GET /api/agent-memory/search?q=`
   - `GET /api/agent-memory/export`（JSON 附件）
2. **序号**：按类型分组，组内按 `created_at` 从晚到早编号，前缀取自类型：`F-01` / `P-01` / `E-01`（两位补零）。序号只用于展示，内部仍以 `mem-…` id 为准；V3 再出正式的命名/对照表。
3. **工作台**（`packages/dsh/client/client.js`）：Opus 5.5 风格的简洁页面——
   - 顶部「记忆 · 共 N · 待审 M」，一行说明；
   - 搜索框 + 「搜索 / 导出备份 / 命令手册」三个按钮；
   - 列表按 事实 / 坑 / 经验 分组，行内显示序号、摘要、日期；空组给空状态；
   - 点条目展开详情：序号、id、维护者、日期、正文（保留换行）、出处列表；
   - 「命令手册」是**小按钮 + 弹层**，列出 `/mem …` 常用命令，强调「日常不需要命令」。
4. **客户端不碰写路径**：列表/详情/搜索/导出全部只读；审批与修订仍走聊天卡或后续 P2 的 GUI 审批。

## 被否方案

- **列表平铺、按时间全局排序**：用户明确要求按类型分组、组内时间倒序。
- **用完整 id 当序号**：不可读；展示序号与内部 id 分离。
- **把手册做成独立页面**：增加导航与维护面；小按钮弹层更符合「新手优先」。
- **导出走宿主 export 目录**：P1 先用 JSON 下载（浏览器可保存）；完整备份/校验留给 P2/P3。

## 证据

- `ci` 全绿：**236 个测试**。新增：
  - `S14.1` 序号前缀与组内时间倒序；
  - `S14.2` 列表分组、计数与序号；
  - `S14.3` 搜索与导出只经 store（含出处可核验标志）；
  - `S14.4` 五个 GUI 路由各自拥有完整 `/api` 路径且仅 GET；
  - `S13.1` 客户端 bundle 断言新增 list/item/search/export 与「命令手册」「F-01」。
- 客户端仍是手写 loader bundle（P1 跟进：迁到 TS + esbuild 构建，减少转义与维护成本）。

## 偏差与回滚

- 详情里的正文按纯文本渲染（不解析 Markdown），避免客户端引入 Markdown 依赖；P2 再评估。
- 导出为单个 JSON（含活动记忆、正文、出处、待审提案），不是目录级 `mem export`；完整备份仍在 CLI/`/mem export`。
- 回滚：删除 `gui.ts` 与客户端页面的新请求，恢复 P0 状态页即可；数据层零改动。
