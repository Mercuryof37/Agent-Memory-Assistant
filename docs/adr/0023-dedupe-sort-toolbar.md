# ADR-0023 · 去重、排序与工具条顺序

- 状态：已实现（待真实桌面复验）
- 日期：2026-10-18
- 阶段：V2 P3.7（UI 行为修正）
- 依据：[ADR-0022](0022-backup-import.md)、[UI 命名规范](../design/ui-guidelines.md)

## 问题

1. 导入恢复后出现「同摘要、同日期」的重复条目（F-03/F-04、F-01/F-05），因为去重比较了 `valid_from`、author、evidence_level；
2. 列表看起来没按日期排序：排序用 `created_at`，显示用 `valid_from`，导入的旧记录被排到前面但日期更早；
3. 工具条里「导出/导入」夹在中间，备份属于收尾动作，应在末尾。

## 选择

1. **内容去重**（`MemoryStore.findDuplicate`）：只看 `kind + abstract + body + error_signatures`，忽略日期、作者、证据等级；导入同内容（哪怕日期不同）只跳过，不新增。
2. **排序**（`gui.ts` 的 `byDateDesc`）：按 **`valid_from` 从晚到早**，同日期再按 `created_at`，最后按 id；序号 `F-01` 与列表顺序都由同一排序产生。每次打开列表都按这个顺序重新计算，不缓存旧顺序。
3. **工具条顺序**：搜索 → 提案 → 偏好与规则 → 命令手册 → **导出备份 → 导入备份**。

## 被否方案

- **只在导入时去重**：DSH 内手工记录同样的内容仍会重复；放在 store 层才是单一规则。
- **按内容哈希去重**：内容哈希包含日期/来源等字段，正是这次重复的根因。
- **清理已有重复**：本次只修「以后不再产生」；已有重复需要显式清理（未做自动删除，避免误删）。

## 证据

- `ci` 全绿：**247 个测试**。新增 `S14.11`（同内容不同日期/证据只保留一条）、`S14.12`（按 valid_from 排序，导入时间不影响顺序）；`S13.1` 增加工具条顺序断言（命令手册 → 导出 → 导入）。
- 客户端重新构建；`import` 报告中的 `skipped` 现在会正确统计跨日期重复。

## 偏差与回滚

- 已有重复条目（本次修复前导入的）不会自动消失；可在 GUI 逐条删除，或后续加「清理重复（保留最新）」入口。
- 排序仍按字符串比较 `YYYY-MM-DD`，对合法日期等价于时间顺序。
- 回滚：恢复 `findDuplicate` 的日期/作者比较与 `byDateDesc` 的 `created_at` 排序；恢复工具条顺序。
