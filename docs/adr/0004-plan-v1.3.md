# ADR-0004 · 方案 v1.3 的简化决定与配置/策略 v2 清理

- 状态：已采纳（方案与配置层；journal 代码未落地）
- 日期：2026-10-17
- 依据：[V1.0-开发方案-v1.3.md](../research/V1.0-开发方案-v1.3.md)、[v1.2 评审](../research/V1.0-开发方案-v1.2-评审.md)
- 相关：[ADR-0003](0003-dsh-compat.md)（S0 结论）

## 背景

v1.2 把设计缺口补成条款，但机制层出现冗余：同一条"已入账/已删除/已决定"的事实分散在 `audit.jsonl`、`.state/ledger.jsonl`、`proposals/decisions.jsonl` 三处，各带哈希链与重放规则；`ProposalInput` 的修订、替代、合并、拆分四个变体只差基数；配置键分三批迁移；S5 的产出被 S3 与 S2b 提前需要。评审给出可省 4–6 人日的简化清单，本次全部采纳。

## 决定

### D31 · 持久化四件套合一为 journal（S2a 实现）

`audit` + `ledger` + `decisions` → `.state/journal/NNNN.jsonl`：append-only、分段 5 MiB、每行 `{seq, prev, at, op, op_id, data}`，行哈希 = 该行字节的 SHA-256，不轮转、不删段；`op` ∈ `record|adopt|delete|decide|audit`。`doctor` 校验链完整与 `journal_head`；文件哈希不在 journal → 隔离。

**理由**：三个文件各自演化出完整的一致性规则（轮转链、重放顺序、tripwire 三方对账），而它们记录的是同一类事实。合一后入账判据、删除判据、决定判据同源，恢复只需"文件 ↔ journal"两方对账。

**代价**：审计不再是常驻的可 grep 文件（由 `mem inspect --audit` 渲染）；journal 不轮转，长期增长（几百条规模可忽略，备份是唯一恢复手段，README 写明）。

### D32 · `ProposalInput` 由 5 变体降为 2

`supersede`（`targets[]` × `replacements[]`，任意 N→M）+ `delete`；修订 = 1→1，合并 = N→1，拆分 = 1→N。所有变体共用一套 `base_hash` 校验与"不部分提交"规则。

### D33 · 删除 S5 独立阶段

`rules/` 解析与映射校验并入 S3（注入必须逐条渲染编号与类别）；`sealed_files` 并入 S2b（与策略校验、`doctor` 同一批）。剩余阶段 7 → 6。

### D34 · 配置与策略升 v2，死键立即删除（已落地）

| 删除 | 原因 |
|---|---|
| `viewer.enabled` / `viewer.port` | V1 不做 Web 查看器 |
| `audit.enabled` / `audit.max_bytes` | 审计并入 journal |
| `policy.targets` | 模型工具没有 target 参数 |
| `policy.approval.mode` / `approval.t1_requires_human` | T1 恒人审，由接口（不注册 `decide`）保证 |

同时：`distill.max_proposals` 默认与上限改为 5（与收尾蒸馏硬上限一致）；`scan.private_tag` 由 `strip` 改为 `reject｜confirm`（不静默剥离）；`schema_version` 与 `policy.version` 升 2。

配置 16 → 12 键，策略 11 → 8 键。代码、`docs/config.md`、`docs/policy.md`、模板与测试同步；`npm run ci`（65 测试）与 `npm run smoke` 通过。

### D35–D40 · 评估集、验收、快照、流程

- 召回评估 60 条 / 16 查询（12 dev / 4 held-out），门槛先测基线再定；
- 验收按 journey 收敛（每阶段 5–6 条），红队用参数化表；
- 快照保留最近 20 个，不设时间与配置；
- 压缩验证 2 次 + 同会话字节一致单测；
- `scripts/stage.mjs <S>` 作为阶段门禁；每阶段 smoke 先加一条失败 journey；
- ADR 一页 + 估/实两列；未决问题进 `docs/plan/open-questions.md`；方案只在阶段边界改。

## 影响

- 后续阶段编号：S2a→S7 中不再有 S5；ADR 编号 S2a=0005、S2b=0006、S3=0007、S4=0008、S6=0009、S7=0010。
- S2a 新增 10 个配置键（lock 3、limits 2、`recall.min_score`、`recall.max_limit`、`inject.counter`、`quota.t0_per_session`、`proposals.max_pending`），一次加完；`recall.limit` 默认 8 → 5。
- S2b 在 policy v2 内**新增** `sealed_files.soul|user|rules`（默认空串 = 跳过），属向后兼容的加字段，不再升版本。
- `S2b.4`（关 audit、轮转两次）与 manifest tripwire 的三方对账验收删除；新增 journal 截断/断链验收。

## 迁移与回滚

- 迁移：已有数据目录需手工把 `config.toml` 的 `schema_version` 改 2、删 `[audit]`/`[viewer]`，把 `policy.json` 改 v2 结构后 `mem policy seal --accept`（见 `docs/config.md`、`docs/policy.md` 的迁移节）。本机无真实数据目录（默认 `<home>` 不存在），仓库内测试与 smoke 均用临时目录。
- 回滚：配置/策略的 v2 改动是单点回退（恢复旧 schema 与模板、删对应文档行），不影响 S2a 之后的代码结构；journal 尚未落地，D31 的回滚只是恢复 v1.2 的三文件设计。
