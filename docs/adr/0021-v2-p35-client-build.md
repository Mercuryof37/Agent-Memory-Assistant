# ADR-0021 · V2 P3.5：客户端半层迁到 TS 构建

- 状态：已实现（`ci` 通过；真实桌面 UI 待复验）
- 日期：2026-10-18
- 阶段：V2.0 P3.5
- 依据：[ADR-0020](0020-v2-p3-distribution-mcp.md)、[V2.0 方案](../plan/v2-gui-and-distribution.md) §5

## 问题

P0–P3 的客户端是**手写 loader bundle**：`client/client.js` 既是源码又是产物，改动靠手改生成文件，容易与主代码风格分叉，也无法用构建工具做压缩、校验与后续类型化。

## 选择

1. 源码移到 `packages/dsh/client/src/index.ts`（React + host slots，保留 `// @ts-nocheck`，类型化留到后续）。
2. `scripts/build.mjs` 新增客户端目标：esbuild 产出 CJS（`--platform=browser --external:react --charset=utf8`），再包一层 `window.__ModuleLoader__.load({ id, factory })`，写到**固定路径** `client/client.js`。
3. 构建产物带 `@generated` 头；tarball 只收 `client/client.js`，不再带 `src/`。
4. `npm run build`、`ci`、`npm run pack` 都会重建客户端；测试读取产物做契约断言（loader 格式、槽位注册、P1/P2/P3 文案与 API 路径）。

## 被否方案

- **保留手写 bundle，只加注释**：没有构建期校验，P4 改 UI 仍会手改生成文件。
- **引入 Vite/tsdown 专用构建**：为一个与宿主共享 React 的 bundle 引入整套前端工程，收益低于成本；esbuild 已是项目唯一构建工具。
- **立即补全 TS 类型**：界面回调多、宿主槽位类型未全部导出，先保证构建稳定；类型化单独排期。

## 证据

- `node scripts/build.mjs` 输出 `built packages/dsh/client/client.js`；产物以 `// @generated by scripts/build.mjs` 开头并保留 loader 格式。
- `ci` 全绿：**244 个测试**；`S13.1` 新增 `@generated` 断言，并兼容 esbuild 的多行 `ctx.slots.inject(` 排版。
- `npm run pack` 产物仍含 `client/client.js`，不再含源码；`scripts/pack.mjs` 的三件套检查不变。

## 偏差与回滚

- `// @ts-nocheck` 是临时手段；P4 前把 `apply/inject`、API 响应与槽位 props 类型补齐后可移除。
- 构建产物仍提交到仓库（profile 直接加载，无需构建环境）。
- 回滚：把 `client/client.js` 恢复为手写版本，删除 `client/src` 与 `scripts/build.mjs` 的客户端段。
