# ADR-0047 · V5.1：检查更新与一键升级

- 状态：已实现（0.5.1）
- 日期：2026-10-18
- 依据：[V5 方案](../plan/v5-robustness.md)、[ADR-0046](0046-v5-group-commit.md)

## 问题

0.4.0 → 0.5.0 只能手动重装；用户问“会不会自动升级”。V5.1 提供**显式检查**和**一键升级**，但不做后台静默更新。

## 选择

1. **检查更新**：设置页“检查更新”按钮才请求 npm registry（`registry.npmjs.org`，失败回退 `registry.npmmirror.com`），8s 超时；比较 semver，返回当前/最新/是否有更新。
2. **一键升级**：点击“升级到 x.y.z”后，服务端只调用宿主 `pluginManager.installBundle('@agent_memory/dsh@x.y.z', {enabled:true})`；安装完成提示完整重启。
3. **不静默**：没有后台轮询、没有自动下载、没有自动重启；用户不点就不联网。
4. **失败关闭**：只接受精确 `x.y.z` 且必须大于当前版本；拒绝 URL/任意 spec；宿主没有插件管理服务时返回 manual 提示，不假装升级成功。
5. **数据不动**：升级只换代码，数据目录不迁移；0.5.0 的 checkpoint/归档仍兼容。

## 边界

- Desktop 包的安装归 Desktop shell 所有；若当前 profile 没有 `pluginManager` 服务，一键升级退化为指引（设置 → 插件），不会提权写 profile。
- 检查更新需要外网；离线时显示失败原因，不影响记忆功能。
- npm 镜像返回的版本可能与主 registry 有延迟；以实际安装结果为准。

## 证据

- S29.1 semver/registry 解析；
- S29.2 仅以 `@agent_memory/dsh@版本` 调 manager；
- S29.3 无 manager 时 fail-closed；
- GUI 路由 `/api/agent-memory/update/check`、`/apply` 已注册。
