# ADR-0028 · V3.1：手动新增、整理建议与 SOUL 路径

- 状态：已实现（待真实桌面复验）
- 日期：2026-10-18
- 阶段：V3.1
- 依据：[V3.0 方案](../plan/v3-visual-and-workflows.md) §4

## 问题

V2 只能通过对话/工具写记忆；用户想在界面上手写一条，没有入口。想从已有记忆里提炼规则，只能靠模型或手工翻列表。SOUL 是封存文件，但界面没有任何"它在哪里"的提示。

## 选择

1. **手动新增** `POST /api/agent-memory/create` + `createGui()`：
   - 类型三选一，摘要必填，正文可选，日期可选；坑必须带 1–3 条错误特征；
   - `author=human`、`evidence_level=user_explicit`，走 `store.add`（校验/锁/journal/内容去重）；
   - 返回 `{id, deduplicated, display}`；审计 `gui-create`；
   - GUI 入口：工具条「＋ 新增」与每个分组标题右侧「＋」。
2. **手动整理** `GET /api/agent-memory/summarize` + `summarizeGui()`：
   - **确定性规则**，不调用模型：统计总数/分类、最近 5 条、错误特征频次；
   - 频次 ≥2 的错误特征生成候选规则（模型指引），带依据编号与置信度；
   - 无候选时给一条通用建议；
   - 只读：不写 RULES、不写 journal。
3. **草稿两段式**：界面勾选建议 →「加入规则草稿」→ 打开 RULES 编辑器并**预填**（按现有编号续号）→ 人点「保存并重新封存」才落盘。关闭/不勾选不产生任何写入。
4. **SOUL 只读路径** `GET /api/agent-memory/soul-path` + `soulPathGui()`：
   - 只返回 `memoryPaths(home).soulFile` 与一句提示，**不读文件、不写文件、不提供编辑/打开 API**；
   - GUI 只展示路径 + 「复制路径」；编辑由用户在外部完成，改完自行 `mem policy seal --accept`。
5. **客户端**：新增/整理使用内嵌面板（非全页跳转）；整理面板展示统计、建议复选框、置信度/依据；设置页新增 SOUL 路径卡。

## 被否方案

- **新增走提案**：用户明确要"手写"，直接落库并记 human 更符合预期；模型侧仍只能 record/propose。
- **整理调模型**：V3.1 先确定性、可测、零依赖；模型总结留作后续可选按钮。
- **整理直接写 RULES**：违反"规则只能人保存"；必须经过草稿与保存。
- **SOUL 提供打开/读取 API**：越权且会破坏封存语义；只给路径。

## 证据

- `ci` 全绿：**252 个测试**。新增 `S14.14`（新增+内容去重+坑校验）、`S14.15`（整理只读、按错误特征出建议、依据 2 条、RULES 不变）、`S14.16`（SOUL 路径函数不触碰文件）；`S14.4` 路由表增加 create/summarize/soul-path；`S13.1` 增加面板与按钮断言。
- 客户端构建成功；工具栏、分组 ＋、整理复选框、规则草稿、SOUL 路径卡均已接入。

## 偏差与回滚

- 整理建议目前只产出「模型指引」；机器门禁需要 check/test 路径，V3.3 再评估。
- 新增条目的 `created_at` 是保存时间，`valid_from` 用用户填写的日期；排序按 `valid_from`。
- 回滚：移除三条路由与面板，`createGui/summarizeGui/soulPathGui` 删除；已新增数据保留。
