# Agent Memory V4.0 更新公告（0.4.0）

> 2026-10-18 · 适用 DSH 桌面 0.2.1-rc.2+ · 包名 `@agent_memory/dsh@0.4.0`

V4.0 的主题是**“记得准、说得清、带得走”**，同时不改变两条底线：记忆是本地 Markdown；写入仍由人审批。

## 一、项目工作树（新 UI）

- **项目总览**：项目卡片显示记忆数、最近更新、相似提示；支持新建/删除项目。
- **项目树**：项目 → 事实/坑/经验 → 记忆；点记忆看详情。
- **焦点关系图**：选中记忆显示 1 跳关系（版本链/相关/来源）；同项目同标签用虚线提示。
- **多选移动**：像相册一样勾选多条，一次移动到其他项目或「未归类」。
- **标签/关系编辑**：记忆详情卡内直接编辑标签（逗号分隔）和关系（相关/来源），关系只连同项目记忆。
- **左侧工作树**：改为卡片式分组、悬停/选中态、勾选框与标题/日期层次，不再是一列裸按钮。
- **删除项目不删记忆**：只移除项目框，里面记忆回到「未归类」，文件不动。
- **详情置顶**：打开的记忆卡片固定在上方；离开视图自动收起。

## 二、数据格式 v1.4

- 每条记忆可带 `project`、`tags`、`relations`（`relates_to` / `derived_from`）；
- `mem_schema: 2`，旧 `mem_schema: 1` 记录继续可读、不重写；
- 新增 `source` 字段保留外部来源（Mem0 导入不会伪造 DSH 会话出处）；
- 导出 bundle 升级 `v2`，仍可导入 `v1`。

## 三、检索与评测

- 新增 `recall.hybrid`、`recall.embedding_weight`；
- **Sidecar 向量**：`AGENT_MEMORY_VECTORIZER` + `mem embed --apply`，插件不内置 ONNX 运行时；
- `recallAsync` 融合 BM25 + 向量；缓存/模型缺失自动回退 BM25 并提示；
- **LongMemEval-style 子集**：24 条记忆 / 10 问，`npm run eval:longmem` 可重放；当前 BM25/hybrid recall@5 均为 1.0（夹具较容易，后续会加改写/跨语言查询）。

## 四、互操作

- **Mem0 导入**：
  ```powershell
  mem import-mem0 mem0-export.json            # 预览
  mem import-mem0 mem0-export.json --apply    # 写入
  ```
  支持 `results[]` / `memories[]` / 裸数组；映射 project/tags/kind/created_at；按内容去重。
- **Memory API v1**：HTTP 响应头 `x-agent-memory-api-version: 1`；路由与 MCP 契约见 `docs/guide/api.md`。
- **MCP**：固定 `memory_search/read/list/propose`，无 decide/record；外部 Agent 仍不能替人采纳。

## 五、侧边栏与体验

- 侧边栏图标改为与宿主一致的线条图标；
- 新建项目改为内联表单（不再依赖被 WebView 禁用的 `window.prompt`）；
- 相似提示只提示、不自动合并；冲突/关系都是计算属性，不写回记忆。

## 六、升级方式

```powershell
dsh plugin add @agent_memory/dsh@0.4.0
# 或在 设置 → 插件 → 从文件安装 agent_memory-dsh-0.4.0.tgz
```

升级后**完整重启 DSH**。旧数据无需迁移：v1 记录按未归类/空标签/空关系读取；如需回滚，安装 0.2.1 即可（新字段会被旧解析器拒绝并隔离，不会误读）。

## 七、验收状态

- `npm test`：全绿（含 S19.10/S19.11/S23.1 等新增用例）；
- `npm run ci`：gates + typecheck + build + tests 全绿；
- `node scripts/stage.mjs S7`：green；
- `npm run smoke`：init → doctor → seal → add/read/recall/rebuild 通过；
- `npm run pack`：产出 `agent_memory-dsh-0.4.0.tgz`；client bundle 构建通过；GUI 路由/图投影/移动/删除覆盖。

## 八、已知边界

- L3 全局图按计划留到 V4.3；当前只有 L0–L2；
- ONNX 模型不随包发布，需按 sidecar 契约自行安装；V4.0 默认仍是 BM25；
- 项目删除/移动是标签操作，不改变记忆 ID 与历史；项目名暂不支持改名。

完整调研与架构原因见 [V4 方向](../plan/v4-directions.md)、[ONNX 必要性](../plan/onnx-necessity.md)。
